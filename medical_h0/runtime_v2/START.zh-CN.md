# MedTool runtime v2：执行修复验收与正式启动

旧formal_medtool_v1失败保留且已公开。新版本不增加24轮/4096输出token/32768context/6000调用/6小时/2GB预算，验收与正式共享调用和时钟。

## 改动

- 将模型反复整体重写的update_plan接口移出共同H0，改为每episode独立的执行状态ledger，记录事实是否读取、真正完成的计算和提交状态。不是只添加防重复提示，也不是原官方planning-on配置的完全复现。
- facts/work/submit/done阶段限制当轮工具可用性；同工具及规范化相同参数返回缓存结果，不再次执行。连续2次无进展或已消耗20轮后只开放submit_answer，留出最后4轮；模型不提交则仍失败，执行器不伪造答案、不自动填gold、不把计算成功当任务成功。
- 提案输入中的嵌套tool_calls/invalid_tool_calls一并做显式字段截断；只保留当前学习答案name/value，去掉重复输入。保留4个学习任务的完整prompt，用官方Nous格式化和真实tokenizer计数，完整输入限20000token。必要时删最旧轨迹事件，必需字段仍超限则失败。模型输入限制未放宽。

## 验收

24项CPU检查通过，覆盖执行阶段、幂等缓存、实例隔离、提交不代写、长嵌套参数、真实工具协议、守卫。固定取原每阶段学习集前2例，共4例真实模型验收，4/4完成提交，每例4–6调用，总20调用；旧失败反馈的重建输入由30895降为11864token。预冻门槛为至少3/4提交、至多96调用、无provider/context失败、旧溢出反馈打包不超过20000token。通过后自动启动正式试验。提交验收不等于医学正确率或HCL收益通过。
