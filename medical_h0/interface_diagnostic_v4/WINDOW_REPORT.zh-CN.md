# 三小时医学 H0 接口诊断窗口汇总

## 已验证的结论

当前主要问题同时存在于适配接口和模型参数构造，不能简化为“医学公式不会算”或“官方工具调用协议无效”。修复了两项明确的桥接/契约错误：非法调用被错误重新包装进历史，以及执行器要求的来源嵌套结构未在工具 schema 中完整声明。精确输入辅助下，六个目标现已能稳定完成真实公式执行和显式提交。

撤去参数辅助后仍只有 1/6 数值正确；再给参考来源束、但不给参数值后为 4/6。它说明来源组织/相关事实定位是重要障碍，同时仍有类别映射、否定布尔含义以及来源语义错误。4/6 中一项还有不支持该参数的跨 episode 来源，不能称四条可信计算链。

## 覆盖仍是独立限制

原八学习任务共有 67 个目标输出。D0 核对为 41 无精确身份映射、8 登记但未启用、18 已启用。已启用中 14 个参考执行与引用提交链可运行、13 个原始值与参考一致；其余包括输入缺失/区间输入及原始分数与类别定义不一致。无精确映射不等于库中绝无实现；有库条目或上游测试不等于可执行、可见输入充分或临床认证。

六目标先按结构可执行性冻结，再比对答案，未按分数换目标。它们不代表 67 项总体，也不能证明自主计算器选择。当前没有 D3/D4 的新结果，没有 HCL 候选或接受更新。

## 本窗口已交付的改进

- v4 已接入审核过的可选/条件参数、规范身份别名检索、结果 episode/来源绑定、引用提交和可恢复上下文。并未做逐项因果消融。
- error_history：非法 assistant 输出保持原文，不重构成字符串参数示例；合法调用路径保留。
- schema_contract：来源嵌套 schema 与现有运行时约束对齐，返回可读字段错误，不自动修复模型 JSON。
- input_domain_patch：对已发现的 MASCC 非法类别静默默认问题，增加上游文档限定的枚举；未知文本在公式前拒绝，合法类别计算不改。31 项合成检查通过，零模型调用，不能称效果改善已验证。

## 后续主线应解决什么

下一次研究应优先让模型提交更简单、可检查的逐参数绑定，明确类别枚举与否定布尔的含义，保留模型实际提供的值和证据；不能由 gold 补齐输入。校验要区分源字段存在、患者/episode 关系、单位/类别转换和医学语义。单纯增加提示词、重试次数或强制提交不能解决这些问题。

先在已有学习内容上按故障类型验收，再冻结未用于改进的内容评估泛化。H0 不必全对，但必须有可稳定得分的基础、可解释的错误和非空历史正确项；之后才适合比较共同 H0 上 Static/HCL，并让 HCL 更新明确的 workflow 层。工具公式、评分器和执行权限应固定，不能把接口修复算成 HCL 的学习收益。本窗口不启动这一步。
