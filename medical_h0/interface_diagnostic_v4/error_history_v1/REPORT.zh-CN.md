## 原始输出定位到的接口问题

执行器要求每个参数的来源为 fact_ids/result_ids 数组与 transformation 字符串，且来源非空、已读取、患者匹配。但是模型可见 schema 只声明 input_sources 是 object，未声明内部属性、数组类型、必填项与禁止的额外字段。D2 因而使用了 fact_id、value、unit 或 transform 等猜测字段。四项计算参数本身与参考一致，来源契约仍被拒绝。另两项存在参数错误/缺失，不能全部归因于来源字段。

校验错误还使用完整 ValidationError 的前 200 字符，长 schema 文本会遮蔽真正缺失的字段。此前采用官方 Nous 只解决调用格式与协议，并不会自动补齐自定义工具的 schema。

D2_PARAMETER_AUDIT 为无模型离线定位：去掉来源校验后，4/6 原始参数集合可由公式执行且等于参考参数。这不是本轮实际成功计算、不是来源医学语义正确，也不能回写为 4/6 得分。原 RESULT 与零执行结果保持不变。
