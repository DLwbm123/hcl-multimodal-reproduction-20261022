# MedTool 医学计算工具与严格评分协议 v3

本轮先验收医学 H0，再有条件启动 Static/HCL。上一轮 runtime_v2 原始运行、失败、评分与预算全部保留；不将新评分回写旧结果。

## 已完成的改动

固定 medical-calc-mcp 源码版本 `45f648d9b37991362df095e4ae41c34c65969caf`，仅使用计算器领域代码，不启动其 MCP/Web 服务。目录共有152项；85项有实际执行覆盖的上游测试且能生成明确类型契约，允许执行。其余目录项标记未启用。目录并不覆盖全部 MedTool 所需计算器，未覆盖输出仍计入完整分母；NEWS与NEWS2、Wells PE与Wells DVT、SIRS与综合脓毒症标准保持不同身份。

模型可调用 search_calculators、get_calculator、execute_calculator；可查看用途、输入字段、类型、单位说明、公式文档和原文引用。必须显式传入参数，不能把源码中的便利默认值当作已知患者事实；未知数值只在类型允许时使用null。结果提供原始值、单位、公式信息、分项与解释，最终报告仍由模型决定和提交。目录检索为固定词匹配排序，不使用病例答案或任务专属候选列表。

通用算术明确限定数字与 Python 条件表达式 `A if CONDITION else B`，说明 `if(...)`、`?:`、字符串、sum、隐式变量等不支持。错误与重复调用不再切换成只准提交；预算耗尽仍失败，不合成答案。预算保持24轮、80工具、4096输出token、32768上下文；每病例900秒检查，并受整轮独立守卫限制。

新评分采用规范身份与显式别名、精确episode匹配；未知名称不能凭疾病词重叠得分，同身份同episode重复提交不取最优值。数字必须是完整数值表达，显式单位须相符，不再提取句中第一个数字。匹配身份与数值正确分别记录。四例旧验收的Alvarez/Wells假阳性与HR/SBP/Shock Index漏匹配均进入回归检查。

## 验证及已发现的失败

1024项上游纯计算测试通过，覆盖85个真正被执行的计算器；40项本地适配/来源边界/公式哨兵/评分/协议/守卫/保持检查通过，无模型调用。上游测试不是临床认证，也不代表152项全部有效。

独立对照 RCP 官方 NEWS2 Chart 1 发现：源码对Scale 2空气呼吸且SpO2>=93%错误加分，原始哨兵失败；已修正为空气呼吸时该项0分并保存LOCAL_PATCHES记录，Scale 1及吸氧分支保留。额外检查涵盖Wells PE全部128布尔组合、GCS全部120组合、qSOFA边界、Shock Index数值及NEWS2阈值。公式来源可追溯，不把通过工程测试称为临床验证。

## 学习集验收与诊断

原8个学习任务各运行一次，使用完整参考输出分母。预冻门槛同时满足：提交至少6/8；选择精确率>=0.80、召回率>=0.40；全部输出正确率>=0.25；已匹配输出正确率>=0.80；工具错误率<=0.20；两个学习块各至少2病例具有正确输出，并有真实医学公式执行成功。任何一项失败都不启动正式Static/HCL，不能用提交率单独放行。

失败后只做一次相同8例的控制诊断：提供要求的计算器名称，不提供数值答案，区分选择困难与后续输入/公式/提交困难。它不是验收重试，不能把第一次失败改成通过；不会增加候选搜索。结果分别记录未匹配、匹配后数值错误、工具执行错误、未提交及公式覆盖不足。未匹配不自动等同于纯模型知识错误，数值错误也可能来自输入提取或最终报告转换。

## 条件性正式对照

仅当上述验收通过，自动接续两阶段工作流HCL及匹配Static。双方冻结相同工具库、严格评分、模型和预算。HCL从空工作流开始，每阶段2个模型自动prose候选；只能更新工作流，不能更新公式、别名、评分器、工具或模型权重。保持原有选择收益与逐正确输出零损失门槛，不放宽5段结构约束。

沿用原32任务角色划分；最终8例已用于旧版本回归，是复用回归面板，不能称新独立确认。学习诊断不访问最终逐例结果进行修改。当前仅开始学习集验收，尚无新HCL收益结论。

整轮从准备阶段起共6小时、6000模型调用、2GB硬上限/1.8GB提前，验收、失败诊断和条件性正式运行共用时钟。仅GPU2，独立父监督和逐调用新鲜守卫；无自动重启。原运行继续使用原GPU4和原预算。
