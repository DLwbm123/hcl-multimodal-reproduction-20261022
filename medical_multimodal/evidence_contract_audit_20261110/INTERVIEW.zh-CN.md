# 医学 Agent 面试讲述：已核实结果与当前机制

本页区分两条实验线，避免把早期医学 VQA 正向结果归到当前 MedRAX 工具策略。面试日期临近也不改变证据标准。

## 两分钟讲述

我研究冻结基础模型时，医学多模态 Agent 能否通过外部经验改善表现。基于 HCL 与 MedRAX 的开源实现，我做医学任务适配，并把系统分成执行与更新两个循环。

执行时，系统读取当前问题和图像，根据经验与当前状态决定动作，工具在当前图像上产生观察，再由 Agent 形成答案。更新时，把交互和可用反馈整理为候选经验；候选冻结后，在当前任务与历史锚点上检查收益、退化和成本，达到门槛才接受，否则保留原状态。模型参数保持冻结。

早期医学迁移实验观察到 VQA 在50例test上从20%到26%，同时定位下降4个百分点。后续固定了任务范围记忆策略，在200个未用于策略选择的VQA开发内容组上，从23题正确增加到40题，绝对提升8.5个百分点，18题修复、1题损失。它是单任务开发确认，不是患者独立的临床测试，也没有证明新能力经过后续任务仍能保持。

目前把外部经验机制接到了原生 MedRAX 工具执行。最新记忆候选虽然被检索，仍未改善结果，还增加了路由耗时，所以被拒绝。逐图报告也没有给出可归因于有效证据的收益。继续排查发现，单图报告会带未经比较支持的时序表述，独立生成的Findings和Impression也可能不一致。随后用92回合对照验证了报告证据准入：实际隔离了部分可疑文本，但13个可评分来源两组仍均7/13。因此来源控制本身没有带来任务收益，下一步需要取得适配问题的有效观察，再研究带来源、支持范围和成本的操作经验。

## 技术追问

**外部经验是什么？** 早期被接受的任务范围VQA状态有10条raw、2条abstract、memory selector版本1，skills0；需要如实说记忆和选择器上下文发生变化。最新MedRAX候选生成4条abstract/6条skills，但验收失败，不是已部署能力。

**与普通RAG区别？** 检索是执行手段。这里额外研究经验状态如何由反馈更新、哪些候选被接受，以及新任务收益与历史保持。当前结果不能证明所有持续学习目标；检索到记忆不等于学会新能力。

**系统怎样调用工具？** 当前本地冻结Qwen控制器输出经校验的动作JSON，转成LangChain工具调用，原生MedRAX图执行process→execute→process；工具观察经ToolMessage回到控制器。不要把项目适配器说成提供商原生function calling。

**为什么没有效果？** 已看到的现象是泛化经验没有触发专业工具动作、部分工具观察不覆盖所需细节、无来源的时序措辞以及报告段落间冲突。它们是有依据的机制线索，不是各自因果贡献已经证明；现用有限对照拆解，而非归因于模型强弱或医学任务必然不适合。

**什么算你的贡献？** 开源HCL/MedRAX不是原创。可解释的贡献是自己实际完成的医学多模态接入、操作轨迹与未知反馈处理、经验状态隔离及配对验收实现。正在验证的证据约束与条件化动作策略不能预称论文创新或已有效方法。

**如何证明持续学习？** 先证明A获得新能力，再证明学习B后B获益且A的新增能力被保留。相同上下文的旧任务持平、小锚点零损失和候选被拒绝都不能单独证明这一点。

**数据边界？** 当前24开发来源此前已暴露，只能用于重复开发验收。48冻结评估与96原确认仍封存，打开前还需资格与来源核查。内容组不等于独立患者；所有unknown不能算错例或正确性奖励。
