# 只读 EHR 短计划 LoRA-GRPO 试验

## 方法与数据

复用 VitalDB 的只读检验环境，排除可重建的 164 位历史患者，冻结 128 名训练、32 名开发、64 名留出患者，每人一题。模型只见自然语言问题、第一页和是否有下一页。任务包含最近值、24 小时均值、必须补读及缺值。评分要求动作合法、使用正确算子、结果正确且当前证据充分，再对工具调用计成本。测试题面使用独立表述；样本按任务形态平衡。

自由 JSON 预检的合法率为 19/128。16 步 SFT 预热未找到优于初始版本的开发检查点；恢复初始权重后重新随机采样的合法率为 17/128。该支线按预设门槛停止，没有启动 GRPO 或查看留出。并行 64 步自由 JSON SFT 的选定检查点在开发集达到 31/32 合法、27/32 成功，未进行留出测试。

随后冻结四种 JSON 动作的受限解码诊断。预检 128/128 合法，107/128 成功。9/32 个病例同组出现成功和失败，12/32 个病例有奖励差异。训练每步实际从当前分布采样，一次产生完整计划，不使用预枚举奖励作为在线轨迹。两组训练均只修改 Qwen2.5-VL-7B 语言层 LoRA，优化至 64 步。

## 留出结果

| 方法 | 有证据支持的成功 | 平均工具调用 | 无需却补读 | 应补读却提前结束 | 非法 |
|---|---:|---:|---:|---:|---:|
| 冻结模型 | 56/64 | 1.078 | 0 | 8 | 0 |
| SFT | 56/64 | 1.078 | 0 | 8 | 0 |
| LoRA-GRPO | 56/64 | 1.078 | 0 | 8 | 0 |
| 简单规则 | 64/64 | 1.203 | 0 | 0 | 0 |

GRPO 相对冻结模型和 SFT 都没有改对或改错任何病例。患者级配对 bootstrap 95% 区间为 [0, 0] 个百分点，反映本面板没有不一致的结果。三组在必须补读的 13 例中都只完成了 5 例，其余任务全部通过。

开发集选定两个训练臂的第 64 步。GRPO 由初始的 25/32 到 31/32，SFT 到 30/32，这些开发增益未出现在留出集。GRPO 共采样 1024 条短计划，111/256 组有非零优势，64/64 步有非零梯度。SFT 使用相同患者顺序的 256 条目标计划，两个训练臂监督形式和完成 token 预算不同。两臂检查了非零梯度、适配器变化、冻结参数版本、关闭适配器复现、保存重载及预测一致性。两张 GPU 的 PyTorch 保留峰值均为 17.20 GiB。从分区落盘到结束约 8 分 46 秒，新增占用约 35 MB。

## 适用范围

本轮检验受限动作决策和执行奖励能否改善只读 EHR 工作流。完整短计划一次生成。实验范围限于 VitalDB 的两个算子和固定分页语义，简单规则构成可检查的参考。公开协议、实现与聚合；患者清单、原始记录、逐例输出和适配器保留在私有运行目录。
