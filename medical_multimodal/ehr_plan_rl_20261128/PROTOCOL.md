# 只读 EHR 短计划 LoRA-GRPO

验证从当前病例的第一页检验回执选择一次短计划。基座冻结，训练仅更新 Qwen2.5-VL-7B-Instruct 语言层 q_proj/v_proj 的 LoRA（rank 8、alpha 16、dropout 0）。所有组使用同一套工具和提示，固定只读，使用病例级排序、分页与真值；策略只见自然语言问题和第一页。统一允许 mean、latest、more→mean 和 more→latest。整段短计划一次生成，按 contextual bandit 解释。

VitalDB 的已知旧 120 人和上一轮 44 人从固定种子与旧面板重建后排除。新面板 128/32/64 人分别用于训练/开发/留出，各患者独立一题。用 1、2、4 条分页，训练和开发使用两种题面，留出使用另一个固定表述。按均值需补读、均值证据已足、窗口内缺值、最近值可得、最近值缺失近似均衡，故留出分数适用于这个分层面板。先对 32 道开发题枚举四种计划，然后冻结基座每题实际采样四次。均值需补读按照新到旧、时间戳唯一和可见末条是否能证明覆盖窗口判定，数值碰巧正确不能代替证据。执行、答案和证据均正确时奖励 1−0.02×计划工具调用数，否则 −1；共享的初始页不计成本。

随机采样温度 1，每组 4 个真实在线样本，每次更新 4 个病例，至多 64 个优化步骤。BF16 基座，梯度检查点，LLM 生成最多 64 个 token。学习率 5e−6，clip 0.2，KL 0.02；以组均值中心化奖励，不按标准差缩放，每批轨迹更新一次。合法率低于 80% 时允许从同一训练分区 SFT 预热 16 步，重新诊断并使用预热策略作 KL 参考。预热后合法率仍低于 80% 或所有组奖励都相同则停止 RL，无成功差异但存在成本差异时仅作为效率实验。规则使用问题词和可见页边界，另有同接口冻结模型和同 64 步成功计划 SFT。按开发成功数、平均奖励顺序选择检查点，等两个训练臂选定后分别评留出；盲测按患者配对，报告分层成功、非法、误停、无用补读、工具成本及 bootstrap 区间。

数据和模型只读复用，依赖 peft 0.15.2 置于隔离目录，无侵入升级。实际运行以首次分区开始，45 分钟以内硬截止，新增长度在 2 GB 前触发存储停止。私有面板、逐例轨迹、LoRA 不公开。脚本运行约定：i1 指向既有 VitalDB CSV，i2 指向上轮无影像 cases.json，env 提供模型路径和 Python 环境。prepare.py 生成分区，train.py 作为 t.py 启动，RUN_MODE 为 0（GRPO）或 1（SFT）。

## 格式预检后的受限解码诊断

自由 JSON 版本的随机合法率低于预定门槛，16 步预热未通过开发选择，按协议停止。两臂均未打开留出集。保留该结果后，用同一冻结面板开启单独的受限解码诊断（RUN_STYLE=1）。四种计划均使用固定 JSON 序列，合法前缀共享，只有可分支 token 需要从模型分布决策。每例从当前策略分布采样四次并只执行所采样计划；优化按宏动作对数概率做 GRPO。冻结、监督与 RL 使用同一个受限分布；SFT 对成功计划做最大似然，两个训练臂仍使用同一患者顺序和 64 步。全部评分和检查点规则沿用上一节。该诊断衡量给定动作契约时的决策能力，不用于论证自由格式工具调用。开发诊断已暴露，留出分区在本次各臂选定开发检查点后才打开。
