# 医学 Agent Harness 持续学习：方法、实验结果与证据边界

**整理日期：2026-11-08。用途：项目复盘、面试准备与后续研究决策。** 本文以仓库协议、运行记录和聚合报告为依据；区分已执行的组件、观察到的结果、未验证的解释与拟议方法。原始图像、问题、答案、病例 ID、训练记忆、逐例模型输出和认证不在公开仓库中。

## 1. 当前结论

项目研究固定模型条件下，如何从历史轨迹构造外部经验，并改变医学 Agent 的上下文或工具策略，以获得新能力并保持旧能力。已经完成 MedRAX 原生工具工作流接入、经验记录与检索、候选查询以及配对评测；已存在若干可讲述的正向开发信号，也保留了多数无提升或退化结果。

**尚未建立可靠、可重复、可归因的医学 Agent 持续学习收益；尚无独立医学验证、可迁移的已学工具 Skill。** v18 双方没有调用 OCR；最新 v19 虽执行六次 OCR，但五次空输出。不能将其代理分数解释为医学正确率，或据此宣称有效 OCR 和经验策略无效。没有对医学 Agent 控制器做 PPO、GRPO 或其他参数强化学习。

## 2. 问题、假设和方法主线

希望保护的对象是当前病例与问题中的正确医学观察、推断边界和原有正确能力。目标是让历史经验在适用条件下帮助 Agent 获得相关事实、采取合适操作并改善决策，而不把历史病例答案当作当前患者事实。

提出的可检验链条为：**触发条件 → 缺失事实 → 有限工具动作 → 当前病例观察 → 独立验收 → 决策及回退**。该链条是主线假设和后续设计，不等于所有环节已被实现或证实。原始记忆注入、静态工具查询、手工裁剪、来源轨迹生成策略均是不同的简化诊断或候选，不自动构成完整可迁移机制。

一个有说服力的能力获取，需要在训练/开发集产生候选并冻结后，在独立分组病例上比较无经验、预算匹配的固定工作流与经验驱动工作流；记录配对 gain（原错变对）和 loss（原对变错）。要评价保持，需先证明 A 学习相对初始状态获得了新能力，再学习 B，分别报告 B 的获取和 A 新增能力的保留；已正确的病例一直正确、或 A 两状态上下文完全相同，都不足以证明新增能力保持。

## 3. 通用 HCL 框架与医学实现

通用框架基于 Harness Continual Learning 公开代码及本项目适配，具体结构是：

1. **Task Interface** 组织当前任务、问题、图像和可见输入。
2. **ExperienceMemory** 分别维护原始交互、抽象经验、历史锚点，以及可选的 Skill 记忆；训练交互与评估读取分开。
3. **Router** 选择 Skill、工作流、经验和工具，执行能力后组装上下文，检查标签泄漏并调用控制器；Trace 记录选择、工具结果和输出。
4. **Optimizer** 生成并评估候选 Harness artifact，依据新任务与历史锚点约束选择、拒绝或回滚；不是使用 PPO/GRPO 的神经策略优化。
5. **Evaluator/Pipeline** 组织批次、模型调用、阶段性评测、日志与状态；具体分母和门槛由实验协议规定。

通用实现入口见 [`hcl/memory/__init__.py`](../hcl/memory/__init__.py)、[`hcl/router.py`](../hcl/router.py)、[`hcl/optimizer.py`](../hcl/optimizer.py)、[`hcl/skills.py`](../hcl/skills.py) 和 [`hcl/pipeline.py`](../hcl/pipeline.py)。路径的设计能力不代表每个医学实验都实际启用这些组件。当前 Skill 默认需两个来源任务的抽象经验，候选主要是工作流指导，`tool_plan=[]`；v16 明确关闭 Skill 层，不能把代码中的 Skill 类当成医学 Skill 成果。

MedRAX v4–v16 复用作者胸片工具工作流，六项能力包括报告生成、分类、分割、MAIRA-2 定位、CheXagent 和 LLaVA-Med；并非每回合都调用所有工具。控制器替换为订阅 `gpt-6.1-sol/high`，因此不是作者同模型数值复现。v17 是独立的单轮图像复核及几何裁剪诊断，不含完整六工具；v18/v19 是 MedCTA 上的 OCR 开发诊断，不可把三类接口的成绩合并或当成同一评测。

## 4. 通用复现与医学多任务迁移

### 4.1 通用多模态复现

资源受限复现采用 Qwen2.5-VL-7B，设置不同于原论文模型和样本规模；严格 HCL 两组均曾因 selector 非法角色失败，之后按声明过的失败样本计分协议恢复。以下是最终平均主指标，不能称为原论文同设置复现：

| 条件 | 平均分 0–100 | 平均遗忘 pp |
|---|---:|---:|
| Raw zero-shot | 60.13 | — |
| Static Harness | 53.08 | — |
| Stability-HCL（恢复协议） | 54.46 | 0.00 |
| Plasticity-HCL（恢复协议） | 51.25 | 3.38 |

Stability 高于 Static，但两种 HCL 均低于原始 zero-shot；单次结果不能证明普遍或因果有效。四类任务的指标不同，平均值是研究中的汇总口径。详见[通用复现报告](../REPORT.md)。

### 4.2 医学分类 → 定位 → VQA 的资源受限迁移

冻结 Qwen2.5-VL-7B，最终每任务 50 例，Static 对比 Stability-HCL：分类 13/50→13/50；定位 22/50→20/50；VQA 10/50→13/50。三任务描述性平均 30.00%→30.67%，VQA +6pp 同时定位 −4pp；单种子不足证明总体稳定优势。定位存在预处理坐标逆映射未明确的混杂，不能将下降全部归因为方法；患者 ID 不可用，患者级独立性未知。

候选选择阶段 VQA 验证从 0/24 到 7/24、48 个历史锚点无遗忘后接受记忆/摘要/技能联合候选；不能把这一开发值当 test 提升。最终记录 10 条原始记忆、2 条摘要、0 条 Skill；36 个提示候选未接受，提示版本仍为 0。历史锚点无损失不等于 test 零遗忘：定位最终有 4 例由对变错、2 例由错变对。详见[医学迁移报告](../medical_transfer/REPORT.zh-CN.md)。

## 6. v16 经验机制与根因边界

A 和 B 各 24 条来源全部保留。H_A 恢复 A 原始记忆；H_B 恢复 A+B 原始记忆。对 B，H_A 从 A 库、H_B 从 B 库各选两条；对 A，两状态都使用同一 A 库。检索在题干上分词、去预定义停用词，按 Jaccard 交并比排序，memory ID 决定同分顺序；固定 top 2、无相似度阈值。两组条数相同，但 token/字符长度不严格匹配。

上下文含历史题干、历史尝试选项语义文字与未经医学独立裁定的训练基准反馈；不附历史图片、病例 ID 或源字母。不能说“完全不使用标签”，也不能把历史目标文字当作当前患者真相。[实现](medrax_task_memory_v16/task_memory.py)、[冻结协议](medrax_task_memory_v16/protocol.json)、[结果](medrax_task_memory_v16/REPORT.zh-CN.md)。

事后审计中，三个原 H0 失分 B 目标在 H_A/H_B 均未取到历史失分记录；这是实际暴露事实，不证明“没检索错误”导致失败，成功经验也可能迁移，错误记录也可能无关或监督不可靠。[来源审计](reports/2026-10-25_12h/REPAIRABILITY_AUDIT.zh-CN.md)。

## 7. MedCTA 快速改进：v18 与 v19

### 数据与边界

MedCTA 有 107 条工具任务。v18 以元数据过滤 OCR 可用且不要求 GoogleSearch 的 90 条，固定种子划出 4 来源、6 开发、12 预留验证、68 预留确认；图像路径不重复不意味着患者或原始资料独立。策略来源轨迹由数据集提供，不视为医生独立裁定。v19 使用原预留验证的前 6 条作为**新开发诊断**，保留后 6 条及 68 确认条目，不得把前 6 条再称独立确认集。

### v18：来源轨迹学习 OCR 使用策略

从 4 条来源参考轨迹生成一份通用策略，在开发输出前冻结；6 个病例对照无经验与该策略，两组最多各两次模型调用，OCR 工具可被调用。12/12 评测格完成，实际 13 次请求包括一次策略生成；两组均 0/6 调用 OCR。严格答案字符串匹配均 0/6：模型多用完整句子、标准参考很短，不能解释为全部医学答错。事后宽松词项覆盖为 4/6 与 3/6，既非预注册指标也未经临床验证，不作为选优或疗效。详见[v18 报告](medcta_ocr_skill_v18/REPORT.zh-CN.md)。

### v19：强制共享真实 OCR 输出

沿用 v18 开发前已冻结的同一策略，在 6 个此前未用于推理的新开发病例上轮转三组：H0 当前图像/问题；固定 OCR；相同固定 OCR 加来源策略。每病例 Tesseract 执行一次，输出共享给两 OCR 组；不是 Agent 自主调用，也不是完整五工具系统。

| 预先定义口径 | H0 | 固定 OCR | OCR + 来源策略 |
|---|---:|---:|---:|
| 参考词项匹配代理 | 2/6 | 2/6 | 2/6 |
| 严格全字符串匹配 | 0/6 | 0/6 | 0/6 |

词项代理的全部配对 gain/loss 均 0/0；不能由此推断三组原文相同或医学判断等同。词项可能错误命中否定或遗漏同义表达，严格匹配也会漏掉语义正确答复；都不是临床真值。

**工具有效观察不足：6 次 OCR 正常退出，其中 5 次输出空文本，仅 1 次非空、98 字符。** 更正：原始参考 OCR 的内层文本为 3 空、3 非空，原报告误将非空外层字典计作文字；其中 2 条参考非空而运行时为空。对五张既有空输出图的事后目视与固定 PSM 11 诊断见[报告](medcta_ocr_diagnosis_20261108/REPORT.zh-CN.md)：三张无明显可读文字，两张含小号边缘字符或数字；替代模式 4/5 非空不等于文字正确，部分可能是纹理误识别。早期两次本地 OCR 环境失败均在模型调用 0 次前，修复字符编码与路径解析后沿原始时钟运行，失败保留。

18/18 单元完成，18 次请求均 ok；累计请求 379.15 秒，输入 124,711 tokens（缓存输入 12,672 为子项），输出 2,984（推理 2,057 为子项）；原始起点到结束 506.40 秒。工具和资源记录、独立时限守卫、保留与禁用范围详见[v19 报告](medcta_ocr_skill_v19/REPORT.zh-CN.md)、[协议](medcta_ocr_skill_v19/protocol.json)与[审计](medcta_ocr_skill_v19/AUDIT.json)。

## 9. 数据划分、证据与后续资格

MedRAX 训练和报告按既定病例/图片及来源线索隔离，但患者独立性不能默认成立；v13/v15/v16 反复使用同一六例已暴露开发面板，不能称独立重复验证。96 个原 MedRAX 确认病例在上述开发轮中保持封存。v17 三例按既有失分和已知标签筛选，非盲法；v18/v19 的 MedCTA 图像路径唯一而患者/源资料归属未知。两套确认集合分别记账，不合并成独立样本数。

下一步优先验证工具输出资格和中间观察能否可靠验收：核对 v19 的开发图像是否有可读文字，检查真实输入、文本提取及参考来源；以可验证样本确定 OCR 输出、空间/单位或工具结果正确后，再研究何种历史经验能条件化选择动作。新假设、数据、对照、资源和选择规则须在评估前冻结；不能在已经看到结果的病例上反复改动后声称独立获益。

跨业务自进化平台的 Trace 切片、自动归因、候选发布与回滚可以作为工程设计方向；当前项目已有局部记录、候选及评测机制，并没有证据表明已交付生产级跨业务闭环。RL 也只能作为可能的后续方案，不能写作既有医学实验使用 PPO/GRPO。
