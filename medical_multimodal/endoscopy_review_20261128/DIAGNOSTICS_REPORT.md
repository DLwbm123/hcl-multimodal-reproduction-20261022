# 内镜读图器的阈值与分辨率诊断

复用原来的 48 帧有掩码阳性、48 帧阴性代理。**默认 0.5 阈值是本面板低召回的明显因素。提高全图分辨率的增益较小。** 这轮只做冻结推理和离线分析，原复核路线的门槛判定延续。

## 原始日志的排序与工作点

分数是将 Yes 与 No 两个 token 的 logit 单独归一化得到的二选一分数。最优阈值在同一面板最大化平衡准确率，仅用于诊断。下表每个三元组依次为敏感度、阴性代理特异度、平衡准确率。

| 重复全图 | 0.851 | 31.2% / 97.9% / 64.6% | 0.192 | 68.8% / 89.6% / 79.2% |
| 左上网格 | 0.836 | 22.9% / 100.0% / 61.5% | 0.192 | 64.6% / 91.7% / 78.1% |
| 右上网格 | 0.815 | 25.0% / 97.9% / 61.5% | 0.101 | 81.2% / 68.8% / 75.0% |

全图按 0.5 判定答对 11/48 个阳性和 48/48 个阴性代理。面板阈值约 0.09 时答对 33/48 个阳性和 40/48 个阴性代理，平衡准确率从 61.5% 升至 76.0%。四种网格和重复全图亦有明显的工作点变化，AUC 为 0.809–0.851。真实病灶裁剪只有阳性运行结果，所以表中只列它的敏感度。

## GPU 4 全图分辨率对照

| 全图像素上限 | 阳性正确 @0.5 | 阴性代理正确 @0.5 | AUC | 面板最优平衡准确率 | 每帧视觉 token 中位数（范围） |
|---|---:|---:|---:|---:|---:|
| 448² | 11/48 | 48/48 | 0.835 | 74.0% | 238（238–240） |
| 768² | 13/48 | 48/48 | 0.830 | 78.1% | 418（342–720） |
| 1024² | 13/48 | 48/48 | 0.824 | 77.1% | 418（342–1320） |

768² 和 1024² 在 0.5 下都相对 448² 救回 4 帧、改错 2 帧，净增 2 个阳性。两档在同面板拟合的工作点见 [DIAGNOSTICS.json](DIAGNOSTICS.json)。视觉 token 按真实编码数计。1024² 相比 768² 只让一帧增加了 token（720 → 1,320）。该计数由逐帧 token 随像素上限单调的检查、全表总增量和最大值变化共同确定。多数帧在 768² 已接近实际可用分辨率，提高上限的额外作用有限。

真实病灶裁剪是原分辨率下的全图加掩码引导的局部图，阳性答对 20/48，重建输入的两视角总视觉 token 中位数为 406（372–476）。在这个对照里，全图单靠提高像素上限未追平这个局部证据诊断。即使给出真实位置，默认阈值下仍有 28/48 阳性未答对。局部聚焦、双图上下文和读图器行为共同影响结果，这里没有单独识别它们各自的贡献。

## 判读边界

448² 复跑在 0.5 下的 96 个判定与原日志完全一致。原日志采用按同帧多动作打包，分辨率诊断按两帧一批。两条路径的二选一分数最大绝对差约 0.062，面板最优阈值约为 0.090 与 0.134，说明该阈值不宜直接外推。阴性代理来自不同的解剖标志类别，AUC 可能受到图像类别差异影响，患者或视频独立性也尚未验证。

结论限定在当前冻结读图器及开发面板。排序分数包含可用信号，阈值选择能在此面板上改善召回与特异度的平衡。全图像素上限上调只带来有限默认召回改善。原固定网格路线未通过进入训练的准确率门槛，这轮未启动任何训练。
