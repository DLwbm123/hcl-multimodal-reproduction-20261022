# 内镜读图器阈值与分辨率诊断

复用 `3e79237` 的 96 帧开发诊断面板及逐帧私有日志。关闭训练，从 pro5000 的 GPU 4 使用同一冻结 Qwen2.5-VL-7B、提示、二选一分数、原始全图、视觉处理器和模型精度。原报告中的动作门槛及判定保持原样。

离线用旧日志的条件二选一 Yes 分数计算 ROC AUC，正负样本打分相等计半个排序成功。分数大于阈值才判阳性。固定 0.5 和面板最优阈值分别报告敏感度、特异度和平衡准确率。最优阈值最大化平衡准确率，并列优先特异度，其次离 0.5 最近。阈值拟合和打分均在同一面板，只用于诊断。真实病灶裁剪只覆盖阳性，报告 0.5 敏感度。它的特异度、平衡准确率、AUC 和面板最优阈值缺少阴性参考。

全图对照将 `max_pixels` 依次设为 448²、768²、1024²，批大小固定为 2，同样的 96 帧按同一顺序推理。448² 新结果对比原日志，记录因批处理形式改变出现的分数和判定差异。报告每种分辨率 0.5 下的阳性答对、阴性代理正确、AUC 和面板内阈值诊断。实际视觉 token 统计融合后送入语言模型的 image token，按视觉网格和 merge size 交叉核对。重建原阳性全图加病灶裁剪的输入只用于统计 token，不重跑其分数。全图和全图加局部视角在视觉上下文上存在差异，比较仅用于定位读图瓶颈。

复用模型和数据，不复制原图。沿用 24 小时硬时限和 1 GB 存储保护。`SOURCE_RUN` 由使用者指向前次完整运行目录，`DATA_ROOT` 指向同一 HyperKvasir 图包。把 `diagnostics.py` 用作工作目录的 `t.py`，将同版 `probe.py` 放在旁边，使用既有 `env` 和 `launch.sh`。原始路径、图像、逐例分数与逐例决策保留在私有运行目录，仅公开代码和聚合结果。
