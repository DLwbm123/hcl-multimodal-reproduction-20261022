# v19 空 OCR 原因的事后开发诊断

## 参考结果计数更正

此前将 OCR 参考轨迹的 `content` 外层字典转为字符串后，误将非空字典计作非空 OCR 文本；此前“六条参考均有文本，其中五条与运行时空输出对应”的表述错误。正确读取内层 `content` 字符串后：六条参考中 3 条空、3 条非空；与 v19 运行时五条空输出相交的是参考空 3 条、参考非空 2 条。参考结果不经独立裁定，非临床真值。保留原版 git 历史，本次更正对应 v19 AUDIT 与项目总报告，旧评分不重算、不改变。

## 图像检查与可解释范围

对 v19 六张已暴露开发图片进行目视，只从是否存在明显文字角度看：唯一默认 OCR 非空图片为有清晰标签的图表；五张默认输出为空的图中，三张未见明显可读文字，两张能看见小号数字或边缘字符。没有医生标注文字边界，目视不等同于穷尽全部图片文字。OCR 是识别图像上的文字，不等同影像描述或病灶识别；对于无明显文字的医学图像，空文本可能是合理结果，不一定是工具故障。

v19 使用本机 Tesseract 5.5.3 默认分割；MedCTA 上游 AgentLego OCR 实现使用 EasyOCR，两种工具及输出格式不同。对包含零散小字或边缘标记的图，默认整页分割可能漏检，但当前证据不允许将每条漏检归因于特定参数。v19 启动时 `/tmp` 路径与编码问题已在模型调用前修复；正式六次工具进程均 exit 0，五次空输出属于返回内容为空，而非先前路径读取错误。

## 固定的后验模式检查

在本诊断调用之前冻结：仅对 v19 原五张空输出开发图，逐张运行 Tesseract `--psm 11` 一次（稀疏文本模式），并发五次、每次 25 秒超时；不看答案、不追加 Agent 推理、不使用其他开发或封存病例。5/5 进程 exit 0，4/5 有非空文本、1/5 仍为空；其中两个新增非空文本来自参考也为空且目视无明显文字的图片，可能是纹理误识别。参考非空的两图中至少有一例出现参考词项的部分表面重叠，另一例没有词项重叠；没有独立逐字符标注，不能给准确率、不能把非空当作有效观察，也不能将这次结果称为 Skill 或 Agent 性能提升。

预先记录的 45 秒诊断级目标没有另设独立外部 watchdog；实际五调用全部退出，累计实测约 0.23 秒，每个子进程均设定 25 秒 timeout。本次工作是已暴露图像的局部事后工具诊断，不更改原实验计时、预注册指标、候选或选样，不能作为独立确认，也不据此在同一病例上继续调参。图像、参考文本和逐例 OCR 内容保存在私有目录，公开只有方法与聚合统计。

## 对主线的含义

v18 的“工具可用”筛选不等同“当前图片有文字且题目需要 OCR”；v19 又固定给所有图片 OCR，导致大量空观察。下一次主线设计应先按可信的任务信号区分需要文字读取与视觉观察的场景，分别使用对应原子工具，并先验证该工具输出是否相关和可核验；在新数据上将来源经验策略与预算匹配的固定策略配对。模型是否真正选择合适工具、利用正确观察并带来净收益，都需要单独验证。
