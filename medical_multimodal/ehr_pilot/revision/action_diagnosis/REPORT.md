## 七例配对动作诊断

第一版规定模型从三个动作标签中选一项，再填写新定义的字段 JSON，同时提示上下文保留原生 API 文档。自由选及指定类型均 0/7；自由组 6/7 至少尝试提交，2/7 模拟受理，指定组 7/7 尝试、0/7 受理。模型多次输出原生 POST 或 FINISH，与新增 JSON 包装冲突。指定分支在第一次参数无效后已进入下一类型，故这版不足以隔离填写能力。完整保留其结果。

据此单独冻结原生接口对照。保持同一类型选择器，自由臂先选下一动作类型，指定臂用参考类型。两臂均预填合法原生动作前缀，模型补全参数或终止答案。前缀从预算中扣除，指定臂模拟受理后才推进参考序列。模拟受理表示 POST 的 JSON 可解析；逐字段和终止检查另计。

| 原生接口 | 首步选择提交 | 至少一次受理 | 资源类型、顺序和数量正确 | 规范终止值正确 | 官方完整通过 |
|---|---:|---:|---:|---:|---:|
| 模型自由选择 | 1/7 | 1/7 | 1/7 | 1/7 | 0/7 |
| 指定正确动作类型 | 7/7 | 7/7 | 7/7 | 1/7 | 1/7 |

自由选择时 6/7 首步选择结束。指定类型后，五道糖化血红蛋白的模拟提交都含正确的必需字段，其中四题最终返回了带嵌套列表和时间戳的错误结构；只有一题整题通过。两例补镁在正确资源类型下仍填错给药途径及速率的数值和单位，最后把对象放入返回列表。两干预臂端到端改对 1、改错 0。原始问题可定位为至少三个独立环节：是否发起提交、提交字段绑定、提交后的终止组织。所有动作均模拟；干预只覆盖原失败集，不能估计对原正确病例的误改率。指定类型和参考计划属于诊断用的额外监督。

## 复现

沿用前一轮 receipt_plan 的私有输入。previous 指向其私有输出，original.py 映射该轮 run.py。本目录依次映射 replay.py 为 a.py、interface.py 为 b.py（同时链接为 interface.py）、native.py 为 c.py。依次执行 start.sh、second.sh、third.sh，参数为四个 GPU 序号，各阶段共用首次启动时钟。对外仅提供程序、协议、报告及聚合计数。
