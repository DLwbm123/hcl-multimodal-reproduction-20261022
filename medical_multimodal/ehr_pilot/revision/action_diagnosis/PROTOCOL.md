# 分离计划、动作选择与执行

先在原 49 题中筛定已失败的 21 题，重跑原选择策略，私有保存每次原始生成、最后答案、窗口和来源统计以及与规范终止值的核对。报告任一输出值与候选统计量的吻合，不把吻合解释为模型内部计算。核验原有逐题指标是否复现后开始第二段。此处 21 题是开发诊断。

第二段只对 3 个原计划结构错误病例将计划替换成参考结构；原生模型继续生成。对 7 个应写病例均运行相同合法动作接口，模型从结束、模拟药品请求、模拟检查请求三类中自由选；另一路由参考序列指定动作类型，但使用同一参数填写接口。两组沿用原学得计划、7 个剩余动作，模型生成值，固定通用字段名称，由解释器组装 JSON。每步至多 384 个生成 token，类型选择占 1；记录参考类型的分支额外获得监督。逐题保存字段/结构、写入尝试、模拟受理与官方评分，增加规范返回值匹配。无真实医嘱。参考执行在相同缓存上独立校验。只公开聚合，3 小时硬截止，450000 KiB 守卫。后续能力验证在不同患者上冻结后执行，不使用这些失败题充当正式验收。

在第一版显式字段接口完成后，审计发现模型多次生成原生 FINISH 或 POST 文本，而新接口仅接受字段 JSON；指定提交类型后若解析失败，原分支还会提前进入终止类型。保留第一版所有结果，另行冻结第二版配对诊断：使用同一类型选择器和原生动作前缀，从该前缀继续解码；两臂统一原生解析与回执。指定类型臂在模拟受理后才进入下一步，重新分配剩余 7 步内的动作，不给予任何字段真值。预填前缀计入每步 token 预算。仅解释相同版本内部的配对，不以挑选最好版本代替原结果。
