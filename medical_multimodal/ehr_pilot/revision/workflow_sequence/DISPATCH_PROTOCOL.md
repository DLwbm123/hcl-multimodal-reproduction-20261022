# 从问题文本选择工作流的补充诊断

首轮端到端实验的 GET 由模型生成，后续工作流类别取 benchmark 已知类别。为剥离这项先验，在原 27 道题和 eICU 72 道组合上增加同一冻结模型的问句分类。问题只暴露原文本，候选菜单覆盖六种已知任务与一个从未联训的组合。以候选字母的首 token 约束选择。GET 独立生成，患者和检验必须完全匹配已记录的当前病例查询，成功后由隔离的回执重放工具提供已验证记录。运行时未使用病例标签或载荷，最终只统计问句分类、查询、已匹配后续计划和完整任务完成。由于前一轮结果已知，本轮作为复用同病例的独立软件路径诊断。

新运行复用上一轮私有目录中的已核实回执，不复制数据库或模型。两张 GPU 分片，20 分钟硬截止、300 MB 提前停止。公开代码和聚合。复现链接上一阶段的模块与查询输出，上一轮代码映射为 `workflow.py`，其运行目录链接为 `previous`。中性入口 `t.py`、`l.sh`。
