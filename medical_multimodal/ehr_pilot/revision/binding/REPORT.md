# 工具参数顺序检查的开发验证

在上海原构建队列中，用 15 人的规范角色示范学习 READ、STAT 和 DIFF 之间的参数关系，在另外 28 人的 31 次访视上评估。每个观测日均作锚点，共 398 日、1,194 题。以下成功数均要求数值与证据同时满足原评分标准。

| 策略 | 成功 | 相对固定示范改对 / 改错 / 保留 | 工具数 |
|---|---:|---:|---:|
| 固定角色示范 | 1188/1194 | — | 4289 |
| 同一触发后的通用提醒 | 1188/1194 | 0 / 0 / 1188 | 4296 |
| 指出具体缺项或减法顺序 | 1190/1194 | 2 / 0 / 1188 | 4295 |
| 按另一折患者的效果选择启用 | 1190/1194 | 2 / 0 / 1188 | 4291 |

明确提示相对通用提醒改对 2、改错 0、保留 1188。6 个触发病例覆盖 5 人，基线在这 6 题上全部答错；1188 道未触发题基线全部答对。两道减法参数反向的题分属两人，每折一人，具体顺序提示均纠正，通用提醒均未纠正。4 道证据不足题分属三人，具体和通用提醒均未纠正。两折都只启用操作数反向检查，交叉选择为 2 人净受益、26 人持平，额外使用 2 次工具。

各题型分母均为 398；固定示范到交叉选择，晨间均值 396→396，周差 398→398，早晚差 394→396。数值题 923→925（共 929），缺值题 265→265（共 265）。这是基线 99.50% 到 99.66% 的内部验证，两个真正分歧的受益患者不足以支持稳健的跨队列主张。同一患者相邻日期的时间窗重叠。模拟器提供实际数值工具回执；题目是回顾性数据查询。

复现沿用前轮上海目录和冻结依赖。在私有运行目录将 terminal/run.py 映射为 prior.py、sensor_context/run.py 为 sensor.py、diary/engine.py 为 engine.py，本轮 run.py 为 t.py；共享前轮的 env、compare.py、diagnose.py 和 pilot.py，source 指向准备好的上海目录。launch.sh 的四个位置参数指定 GPU。公开结果仅含聚合计数。
