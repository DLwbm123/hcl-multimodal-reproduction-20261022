# MedAgentBench 开发验证：从示范约束首条 FHIR 查询参数

在旧 83 题构建集内，58 题的示范首个 GET 使用可从问题读出的 MRN。既有普通组 58 次首个 GET 中有 28 次没有按示范写出检验代码，人工流程组 58 次中有 14 次。旧历史 40 题、外部病例均冻结。本轮评估同项目原 77 道开发验收题，与构建患者互斥；这些题以前用于其他策略评估，明确为开发验证。

从按原词法检索选中的、已经通过验证的流程示范中读取首个 GET 的资源路径、查询字段和常量。仅当示范包含 MRN 插槽且当前题面有唯一可见 MRN 时检查。行动方首次提出 GET，收到实际回执后，若资源路径、单值患者字段或单值检验代码与示范要求冲突，最多反馈一次。患者和检验代码仅取自题面与检索示范，不据 case ID 选策略，不读标准答案；下游查询、数值计算、模拟写入及结束均由原模型继续完成。未选中该范围的工作流也纳入全体分母。本次不依据外部血糖队列调整查询规则。

主要比较冻结流程卡作为基础时，A 原轨迹、B 同触发只提醒重查、C 同触发指出错误资源或字段和当前应绑定的值。另以原无提示轨迹重复同一比较，用于确定原卡是否已覆盖相同错误。首个动作、回执和历史固定；未触发三组共享原轨迹，触发后 B/C 从相同前缀继续实际调用本地 FHIR，各次模型上限八步含已执行首步。与历史相同的模型、提示模板、词法匹配、1024 token 卡预算、每步384 token，POST 只做模拟。端到端主要指标沿用基准官方评分加原条件任务正确查询的门槛；另报对所有需查询工作流都必须看到正确检索回执的严格评分、有效查询比例、改对改错保留、收益患者方向和成本。将查询修好与任务最终通过分别统计。不得对原 77 题选择新阈值并当作独立检验。

首次运行限三小时，含独立服务初始化。用只监听回环的 HAPI 数据库副本，新增预计 4.6 GB，目录守卫 6000000 KiB；记录初始主机历史相关任务占用约 22.8 GB，保持授权累计低于 50 GB。仅发布统计和代码，不发布轨迹或数据。
