# 从可核查的开发错误修订条件操作流程

问题：基于开发轨迹定位第一次有证据的动作不一致，再让冻结模型写一次局部流程编辑，能否在新开发患者中修复需要写入的分支，并保留旧策略的成功？

沿用开发 160 题的原 83/77 患者隔离划分。仅按题面检索到补镁或补钾的工作流参与修改；旧策略分别采用冻结的镁卡和无记忆回退。两组模型、FHIR 视图、原评分及取证要求、贪心、每例八步与每步 384 token 均相同。建设侧使用所有命中题，保留旧策略实际轨迹。在建设和验收两侧，每道目标题另构造两个独立模拟患者，保留题目和工具语义，一例应写、一例不应写。生成规则只依赖预置种子与题目顺序，旧测量为干扰项，较新的测量决定分支；真假病例、两个分支分开计分。真实患者和模拟标识跨侧隔离。模拟数据仅供基准环境研究。

离线用程序参考执行与原评分核实目标。对每条失败，按时间序列定位可观察的首个偏差：取证前写入、缺合格查询、分支错、写入目标/顺序错误、写入 JSON 与参考首个字段偏差或完成失败。字段差异用于定位候选解释，不自动等同于官方判错原因。按来源与预期分支记录。冻结模型仅据建设侧摘要、原记忆、题面规则及建设侧通过评分的参数化写入结构，每类生成一个最多 256 token 的有界新增指令；不能改变共享工具或答案评分。记录模型生成的原文，验收前冻结。隔离验收比较原策略与候选的配对改对、改错、共同成功、需写入成功等。工作流仅在真实验收侧至少新增一道需写入成功、无任何真实退化且模拟各分支无退化时采纳；实际覆盖不足单列，当前外部 100 人和历史 40 题不用于改卡或验收。未经采纳的候选不计入部署增益。

本授权起累计核算 pro5000 新增的研究目录。首轮 /data/bmw/jobs/e261126g 起始为零，预计低于 8 GB，复制一份原服务快照，不复制模型。文件上限、总时间两小时和独立磁盘看护，首轮在 10 GB 前停止，后继实验合计严格小于 50,000,000,000 字节。只公开汇总与代码，包含病例的轨迹和逐题诊断保留在服务器。

## 实现与复核

本轮实现 HCL 风格的开发反馈记录及 SkillOpt 风格的一次有界文本编辑。当前对照检验整套更新带来的配对变化；两部分的独立贡献需要单独消融。诊断表记录的是可观察动作与可验证参考要求之间的差异，模型的隐藏思考不可观察。保留原始条件工作流的真实题数上限，使用机制探针弥补建设侧无法生成正例的问题，探针只提供开发教师监督。

复现需要在私有独立工作目录只读复用上轮 library.json、partition.json、gate.json 和 compare.py、pilot.py、diagnose.py。使用现有预装快照的独立副本创建 HAPI 服务，回环地址及 SOURCE、MODEL、PRIOR、解释器设置同原 transfer/PROTOCOL.md。将 revise.py 作为 w.py，launch.sh 作为 l.sh；env 保存既有环境设置，db.pid 为本轮独占数据库服务的硬超时进程。启动 l.sh 时传入两块可用 GPU，外层超时与服务共用初始时钟。训练与验收均只取目标题，其他工作流按冻结题面检索机械复用旧行为；这些未运行的任务不计入实测保留数。每个模型进程依次执行一份工作流。result.json 汇总真实和模拟分支及采纳判断，counts_5.json、counts_9.json 是建设侧错误分类，逐病例轨迹、医疗记录与生成器输入保存在私有目录。

## 持续实验交接

此轮起始工作目录为 pro5000 的 /data/bmw/jobs/e261126g。后续实验先核对本轮及之后所有目录和共享产物实际新增占用，再分配可用预算，不按轮次重置总可用空间。每次验收完成都要给出实际改对、改错、保留、条件分支分母及首个动作偏差。优先保留能说明新机制的对照；若无可验收的真实需写入病例，记录证据缺口，选择新的独立开发来源，或在明确标注的模拟条件下继续检验具体机制。若写入行为改善但验证字段出错，应以已有轨迹确认是哪一字段或哪一步，再冻结下一次待检验的修订。数据不离开约定边界。

运行恢复记录：补钾验收首次在一次 FHIR 只读查询的 25 秒等待上限处退出，未完成批次未计分。此前 20/27 条旧策略记录已原子写盘。补镁验收已齐，保留全部已完成记录和原编辑，补钾从断点恢复，仅将未完成部分 HTTP GET 等待延长至 120 秒，仍共享原来两小时截止。resume.py 调用原运行和报告函数。数据库服务在整个恢复过程中保持同一实例。
