# 从已验证示范归纳可执行分支

前两轮明确了正确检索后仍有错误写入、无效提交及错误终止。固定检索模型和原卡，测试从独立开发示范归纳的可执行流程能否在当前模拟工作流改善最终成功数。此轮属于有参考示范监督的单模板机制研究。

沿用 eICU Demo 的患者划分。每层最初预留的 24 人中 16 人构建，8 人做开发验收（合计 48 与 24）。保留此前使用的 24–71 号患者作历史记录，本轮只在每层 72–95 号的新患者上验收，共 72 人。按固定排序分配，无结果筛选。开发参考动作由既有基准参考程序产生并由官方评分器验证，不能据此声称无监督学习、临床医嘱复现或跨工作流迁移。真实输入是 eICU 检验。固定题面、基准时钟和模拟提交。

四个配对策略共享原卡模型实际生成的首个查询与可见回执，仅符合当前患者及检验时启用候选。A 为原卡模型运行；B 对合格回执一律提交开发示范中的终止答案；C 从构建病例学习按最新值和缺测判断能否停止，需写入时回退 A；D 在 C 上加入从相同已验证示范归纳的写入模板，绑定本患者，按构建示范拟合可变数字字段。最新值比较阈值取构建集分隔点；阈值并列按固定顺序解。固定字段仅限此题面/时钟，不外推。每阶段在 24 个独立开发病例上通过分支全对、参考动作完整匹配才启用，否则回退；不看本轮验收标签来修改流程。B–D 通过离线配对回放评分，沿用同一个模拟 POST 回执和官方评分；任何回退均取相同配对的 A 轨迹。验收病例的参考路径及源记录一致性在冻结候选后检查，仅用于计分与核查。
  
主要比较 D 相对 A 的取证合格成功数、改对、改错、保留。C 对 A、D 对 C、B 对 C 为机制对照，同时报告分支、错误停止、错误写入、首次查询命中、开发启用决定。若全停与 C 在总分上持平，单列需写分支的动作，不能把全停策略的分数归为自适应收益。两小时硬截止，450000 KiB 目录保护、单文件上限和累计 50 GB 上限。模型和源表只读复用。
