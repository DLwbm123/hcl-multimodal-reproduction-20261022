# MedThinkVQA 首轮选图数据

选用 [UMass BioNLP 发布的 MedThinkVQA](https://huggingface.co/datasets/bio-nlp-umass/MedThinkVQA/tree/3a0b076f5116c6237ca94bb71fc14066cddf7cdc)，固定版本 `3a0b076f5116c6237ca94bb71fc14066cddf7cdc`。许可为 CC BY-NC-SA 4.0。服务器私有目录为 `pro5000:/data/bmw/HCL/private/medthinkvqa_20261125/`。保留原始 `images.zip`、`train.jsonl` 和 `test.jsonl`。首轮病例的图像单独解出，其余可按需从 ZIP 取用。

## 首轮抽样

两组病例均来自官方训练集。预先固定随机种子 20261125，按病例编号排序后打乱。先取 32 例用于开发，再取 64 例留出作一次配对诊断。输出选取独立于模型预测和得分。官方测试只使用病例编号、图像编号和规范化的病史做交叉排重。公开索引没有患者编号、医院或论文来源编号，划分仅支持病例层面的结论。

病例至少保留四张有检查类型的不同图像。剔除工作流、后处理、标注示意图和 PACS 截图类别。第一张图之后至少有两类不同的候选检查，使模型有机会根据已读证据选择。过滤病史中完整出现任一选项文字的病例。用病例编号、去除路径的图像编号和规范化病史做组间去重。该筛选偏向影像选择较丰富的病例，结果不能直接外推至全部官方样本；它也无法识别全部近重复图像、同义改写或图中烧录文字。

## 运行时读取

- `pilot/{development,heldout}/inputs.jsonl` 含内部病例编号、病史、诊断选项和候选图目录。候选目录只提供视图编号、模态、检查子类型。后二者取自官方元数据。两种策略使用相同目录。
- `pilot/{development,heldout}/images/<病例编号>/viewNN.*` 保留原始图像字节，文件扩展名按实际格式确定。取图工具将所选视图编号解析到这里，每次只回传被选中的图。
- `pilot/{development,heldout}/answers.jsonl` 只交给评分器。原始 JSONL 中的标题、逐图图注、综合影像所见、讨论、ICD 编码、正确答案均不传给策略。
- `pilot/summary.json` 记录版本、划分、筛选计数和图像解码数量。本地 `summary.json` 为同一汇总。

拟议配对诊断的两组共享第一张图，每例最多看三张不同图。固定组按原有顺序看图；自适应组在共同首图后按病史、已见图和候选目录选后续图像。冻结相同模型、图像分辨率和调用预算。分别记录两组同对、同错、改对和改错病例数，同时记录选图和实际调用成本。留出病例只用于冻结后的比较。

## 重建

在含上述三个固定版本原始文件的目录上设置 `DATA_ROOT`，用装有 Pillow 的 Python 执行本目录的 `prepare.py`。脚本核对 ZIP 目录是否覆盖官方索引中的全部图像路径，并解码首轮选中的每一张图。准备完毕后一次性生成 `pilot/`，目标已存在时停止，保留既有划分。
