# MedThinkVQA 条件观察技能实验

每例固定使用原排序前三张图。所有诊断分支共用 Qwen2.5-VL-7B、病史、完整选项和最终诊断提示。通用观察只看单图，鉴别诊断导向的观察额外接收病史和所有选项，每图生成上限相同。两种观察都禁止直接给出诊断。临床正确性由数据集选项答案衡量，征象覆盖通过经清洗的图注片段自动评估，另用冻结的 3B 模型检查图像支持度。完整选项名的逐字匹配检测不到所有释义泄漏。

从历史面板选 32 例拟合，重新生成鉴别诊断导向的观察，保留与描述性参考的覆盖反馈。HCL 按分层整理原始记忆和抽象记忆。优化器生成可视触发条件、操作、跳过条件、两个不同训练病例的漏报支持例及一个对照例。包装器将单条编辑交给 SkillOpt 的 append 实现。程序核验支持例的 ID、病例去重和漏报分级；支持例是否表达同一临床机制、对照例是否真正相似，没有人工核验。若结构化编辑失败，只执行固定基线的开发对比。

验收用新的 32 例，在两层各取 16 例，排除全部 608 个既往病例。3B 模型先只看单图和适用/排除条件，对整个验收集标记适用性并落盘，之后才生成待测观察。候选在验收阶段对所有图执行，以便同时估计适用及范围外的效果。阈值见 design.json。通过才开启另外 128 例，在两层各取 64 例。自动路由由 7B 模型决定。各策略共用确定性路由、观察及其缓存结果，固定策略不使用路由决定。报告每个病例的三个视图调用预算及实际去重后的模型调用总数。

运行目录复用历史运行器的 acquire、prep、previous_learning、panels、patch_format、upstream_skill、review 和 start 模块，将 finding_skill/run.py 映射为 prior_skill.py，将 findings/panel.py 映射为 panel.py。第二套权重由 BLIND_ROOT 提供，历史两个 64 例面板由 FINDINGS_RUN 和 SECOND_RUN 指定。私有病例记录留在服务器；gate.json、可选 confirmation.json 只含聚合指标。重复执行应使用新目录，启动器由 supervisor 单独写入 LAUNCHED.json。
