## 工具和比较范围

执行器只有一项动作 `open_view(view_id)`。它根据参数在私有病例目录中打开实际图像，返回像素，并记录返回的视图编号与尺寸。首图相同；后两步均让冻结模型从合法参数中选择。自适应组执行所选参数，固定组执行目录中第一张尚未打开的图。固定组也实际运行选择模型以匹配计算预算。最终答题时对已取的三张图按目录原顺序排列，不提供选择理由。每组每例均执行三次取图、两次选图前向和一次最终答题前向。留出组每个策略各调用工具 192 次、模型前向 192 次。

两组在相同所选图集合上的最终答案通过了一致性检查。实验支持“模型能改变取图参数”，尚未显示这些改变改善诊断。旧项目的 `answer_visual_question` 未注册。此处的 VQA 是最终评分任务。当前设计只检验病例内取图，未进行多工具协作或跨病例技能更新。

## 复现入口

先按上一级 README 准备私有数据，使用本目录的 design.json、check.py、run.py 和 score.py。沿用同仓库 medical_multimodal/skill_edit_20261125/launch.py，使用具有本地模型和 Pillow 的既有推理环境。环境变量 DATA_ROOT 指向已准备的 pilot 目录，MODEL_ROOT 指向冻结模型，RUN_ROOT 为新的私有输出目录，PILOT_ROOT 指向带有既有运行环境入口和资源监督器的服务端项目，RUN_GPU 为所选卡，PYTHONPATH 包含 RUN_ROOT。使用中性进程入口启动。权重、原始病例和逐例预测保存在私有服务器。result.json 只含聚合统计。
