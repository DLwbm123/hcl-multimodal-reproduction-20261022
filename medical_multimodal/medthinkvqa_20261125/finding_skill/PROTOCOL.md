# 从漏报反馈学习逐图观察步骤

前一轮冻结模型在有参考征象时答对 30/64，在模型先写自述时答对 22/64。本轮只允许修改从单张图生成观察笔记的指令，模型写笔记时看不到病史、选项、参考征象或诊断答案。最终诊断提示、模型、三张原图和笔记长度统一。两个推理方案都需要三次观察笔记生成和一次诊断前向。

用前一轮 64 例中每层前 16 例的自述、核查后参考片段和覆盖反馈构建 HCL 原始／抽象记忆；两层合计 32 例。复用原项目 RawMemory 和 AbstractMemory 的限量保留与抽象逻辑，每层保留四条原始记录和两条抽象。训练反馈仅涉及图像描述；正确诊断不进入提案。冻结生成器基于两层记忆提出一次通用图像检查步骤编辑，复用 SkillOpt 的原生补丁函数。只允许在现有技能上追加一处，格式错误最多修复一次。

每层其余 16 例共 32 例用于开发验收。候选需增加两层合计的覆盖征象数，且每层最终答对数均不下降。未通过则回到初始技能。这里的开发病例已经用于前一轮瓶颈诊断，独立性能判断只使用新的确认集。若没有合法候选，保留失败回执，诊断和部署均使用初始程序。

排除先前全部 544 例后，每层按原有顺序新取 32 例作配对确认。无论候选通过与否，均报告其冻结版本相对初始程序的覆盖变化、诊断改对与改错；拒绝的候选只用于诊断。确认病例的自动核查参考征象只交给评分模块。判定沿用主实验的盲审提示。覆盖率针对获得参考片段的视图，不能当成临床敏感度。初步支持需同时增加覆盖的参考征象、净多答对，且部署准确率的配对双侧检验 p < 0.05。

复现时使用本目录的 design.json、check.py、run.py。复用同一项目的 findings/run.py 为 review.py、findings/panel.py 为 panel.py、prepare.py 为 prep.py、selection/run.py 为 acquire.py。使用 learning/run.py 为 previous_learning.py 及其 panels.py、原生 HCL 和 SkillOpt 辅助依赖（见 learning/PROTOCOL.md）。环境变量 FINDINGS_RUN 指向上一轮的私有输出目录，其他环境与 findings/REPORT.md 一致。原始病例、历史反馈、补丁草稿和逐例输出保留在私有服务器。
