# MedThinkVQA 上 HCL 与 SkillOpt 的快速配对实验

主问题是联合方法能否把先前病例的反馈转化为后续病例的诊断收益。主要比较预先指定为 HCL＋SkillOpt 对无学习组。单独使用两种方法的结果用来解释联合结果。所有组使用冻结的 Qwen2.5-VL-7B-Instruct、相同候选目录、相同三张图预算、相同分辨率上限。学习得到的指导进入两次取图决策和一次诊断决策。每个病例只给一次最终诊断机会。

| 组别 | 从训练反馈获得的状态 | 更新规则 |
|---|---|---|
| 无学习 | 共同的初始指令 | 全程固定 |
| HCL | 原生 RawMemory 保留有代表性的成功和失败，AbstractMemory 提炼解题与防错经验 | 当前验证组答对数严格增加，第二阶段还要求第一阶段验证组答对数不下降 |
| SkillOpt | 从预测、已开图类型和诊断反馈提出一处指令编辑，通过原生补丁函数应用 | 当前验证组答对数严格增加 |
| HCL＋SkillOpt | 用该组自己的历史轨迹生成经验，结合新经验提出技能编辑 | 经验与技能一起提交或回退，采用 HCL 的新旧验证要求 |

为了快速得到结果，每组每阶段提出一份候选，技能编辑最多修复一次格式。HCL 每阶段最多保留四条原始经验，推理时按词汇重叠度取一条及其对应阶段的两条抽象经验。SkillOpt 使用单处文本编辑及验证，不涵盖原论文完整训练日程。每组各自从当前已接受状态出发学习，同一病例、同一指导产生的相同推理请求跨组复用。推理预算相同，另报学习开销。

## 数据与顺序

使用上一轮固定种子得到的去重病例池，跳过已经用于选图实验的全部 96 例和超过当前动作编码容量的病例。按候选图中的检查模态分两阶段，有 CT 的作为 A，其余作为 B。按既有顺序分配，不按模型表现挑病例。每阶段用 16 例提供训练反馈，16 例验证候选，64 例最终确认。总共 192 例。公开数据允许病例级去重，无法核实患者独立性。两个阶段都是诊断 VQA，只能检验这一次数据分布变化后的保持性。

## 判断标准

- 冻结最后被接受的状态，在同一批 128 个新病例上逐例比较。主要报告联合方法相对无学习组改对、改错、净增的病例数，以及双侧精确 McNemar 检验。预先约定净增为正且 p < 0.05 为本轮的初步支持。较小收益可能无法在这一规模上分辨。
- 分别报告阶段 A 和 B 的确认表现。在 64 个新 A 病例上比较完成阶段 A 和完成阶段 B 后的同组状态，以观察历史保持情况。
- 对每组最后一份候选另做预先约定的诊断，即使它被验证门拒绝。这个结果不用于重新选择或部署候选。分别回答“候选能改变什么”和“按方法实际部署后是否获益”。
- 只允许训练病例的答案进入学习反馈。验证答案仅用于计数与接受判断，确认答案在各组预测保存后才进入评分。原始病例、记忆、技能草稿和逐例预测留在服务器私有目录。

## 复现入口

在新的私有 RUN_ROOT 放置本目录的 run.py、panels.py、check.py、design.json，另将上级 prepare.py 以 prep.py 命名、selection/run.py 以 acquire.py 命名。复用同仓库 medical_multimodal/skill_edit_20261125 的 launch.py 以及 upstream_probe 的 patch_format.py 和 upstream/skill.py（在运行目录命名为 upstream_skill.py）。PYTHONPATH 包含运行目录和带 hcl.memory 的原项目 Python 根目录。设置 RAW_ROOT 为先前准备数据的根目录，DATA_ROOT 和 RUN_ROOT 为本轮输出目录，MODEL_ROOT 为 Qwen 权重目录，PILOT_ROOT 和 RUN_GPU 为启动器所需的既有环境和 GPU。使用原启动器及其资源监督器。两阶段完整条件、资源上限及指标见 design.json。
