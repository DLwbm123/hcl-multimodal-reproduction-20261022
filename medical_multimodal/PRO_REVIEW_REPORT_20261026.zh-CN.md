# 医学 Agent 持续学习实验报告：现有错误、工具可修复性与数据路线决策

日期：2026-10-26。用途：供 Pro 独立审阅，判断下一步应继续核验现有病例，还是转向带过程标注的数据。实验结果依据截至提交 `4873961` 的公开报告与审计；本文没有启动新实验、下载新数据或改变既有评分。

## 1. 当前结论与待决问题

**尚未建立可信、可重复、可归因的医学 Agent 持续学习收益，也没有形成经过独立医学验证的工具修复 skill。** 已确认若干记忆、查询、状态更新和图像操作确实执行，但工程介入没有转化为达到冻结门槛的能力获取证据。

最新 v17 从15个已暴露失分病例中选出3项可执行几何操作候选，完成6次配对复核。原图复核与原图加裁剪均为0/3，gain/loss=0/0。其范围仅是有限裁剪辅助诊断，不能据此断言其他工具操作也无法修复，或现有数据整体不可用。

**当前建议供审阅：**降低继续在现有题库中盲找修复病例的投入，优先核验具备过程真值的新数据；现有题库保留作错误分析和将来迁移诊断。这个建议基于验证条件和投入回报的判断，并不是已经证明“必须换数据”。尚未执行数据迁移，也未取得新数据上的任何成绩。

## 2. 研究目标与实际系统

目标是在医学 Agent 上学习可迁移的经验或操作 skill：训练反馈应改变后续病例的操作与观察，产生新能力；之后学习任务B，需同时获得B能力并保留A阶段新增能力，且不能靠牺牲基础正确病例抵消总分。

基座来自 MedRAX，沿用作者 revision `dae30e2f136ef0b2a40885a4c335386e9ffad052` 的原生工作流。六工具依次为胸片报告生成、分类、分割、MAIRA-2定位、CheXagent、LLaVA-Med。控制器替换为订阅 `gpt-6.1-sol/high`，不是作者GPT-4o的同模型数值复现；后端模型快照和采样seed不可固定。

v4–v16主要沿用原图、问题提示、六工具及最终字母评分，分别干预记忆表示、检索、经验介入时机、查询、图像预处理或持久状态。各轮没有更新控制器权重；也不能把这些受限变体统称为已经完成全部HCL技能学习机制。v16明确关闭skill层，只检验原始经验状态更新。

**v17接口单独说明：**它使用Sol High单轮结构化视觉复核与PIL几何裁剪，没有加载整套六工具、没有运行原MedRAX完整工作流，也没有学习动作策略。其分数不能与前述完整Agent成绩直接比较。

HCL原论文也不保证VQA单项获益：表2的VQAv2，Zero为85.47，Plasticity为79.80，Stability为79.33；跨任务平均提升不能直接推断为医学VQA提升。[HCL原文](https://arxiv.org/html/2608.19013v2)。MedRAX基准问题经GPT-4o生成与自动质检；这提示核验题目监督的必要性，不构成已经确认错标的证据。[MedRAX原文](https://arxiv.org/html/2502.02673v2)。

## 4. 最近的可修复性审计到底发现了什么

### 4.1 来源和检索

v9的48条训练来源中A/B各24，各20条基准正确、4条失分。8条失分均有未解决的复核问题，不能把它们直接升级为正确医学纠错规则。

v16对6个B目标每次检索2条来源：H_A只有1/6目标收到历史失分记录，共2/12来源位置；H_B也只有1/6，共1/12位置。原H0失分的3个B目标在两种状态下均未收到历史失分记录。所有来源仍保存在bank中。[事后来源审计](reports/2026-10-25_12h/REPAIRABILITY_AUDIT.zh-CN.md)。

这并不证明“没有错误来源导致零收益”：成功经验也可能迁移，错误经验也可能不相关。当前缺少的是来源错误类型、缺失事实、具体修复动作与目标适用性之间可核验的联系。

### 4.2 v17的候选、操作与结果

总体为v9训练48例中的全部8个失分，加v7报告48例中的全部7个失分，共15例、28张已有图。全部材料已暴露，标签在候选筛查时已知；不是盲评或独立留出确认。12例暂留待输入/监督核验，不能称永久不可修复。

| 匿名候选 | 缺失事实候选 | 已执行操作 | 配对结果 |
|---|---|---|---|
| C03 | 气管装置与纵隔空间关系 | 保留原图，加中央区域放大 | 原图复核与操作辅助均失分 |
| C11 | 局部椎间隙/终板属性 | 保留原图，加脊柱局部放大 | 两组均失分 |
| C13 | 不同肺区随序列的变化 | 对三原图逐图生成左右区域放大，保持图序 | 两组均失分 |

8张派生图的来源绑定、像素框、原图前缀、顺序与附件数量已核验。两个条件都提供相同的既有未验证初答，分别再复核一次；操作组额外提供裁剪图和几何映射。三配对最终字母均未改变。

**对v17必须保留的限制：**

- 几何框是手工冻结的候选，没有学习，也没有由定位/分割工具自动决定；没有覆盖多种实质不同的工具动作。
- 独立病例只有3个，没有重复、正确病例误伤对照或独立迁移集；不足以排除小效应或其他操作有效。
- 两组均看到旧初答，可能存在锚定；没有隔离这个因素，不能说它造成失败。
- 操作组图片与token成本增加，未精确匹配；未向模型提供独立验证的医学观察事实。
- 文件图序可核对，不等于临床时间戳已验证。空间属性、局部结构判断和选项分歧也未获专家裁定。

因此，v17支持的结论是“这三项有限几何干预未显示开发集修复”，而不是“已经完成Pro建议的完整可修复性验证”。尤其尚缺独立观察真值、充分的工具适配和适当的上界诊断。

## 5. 已知问题、未证实解释与研究空缺

| 层面 | 已有证据 | 仍未知/不能宣称 |
|---|---|---|
| 监督与输入 | 部分问题的解释超出当前输入，或有选项重叠、尺度/时间依据不足 | 不能判整个数据集错标，也不能把模型与gold分歧直接算医学纠错 |
| 工具观察 | 有bare No、Not matched、空串或破损文本；查询/图片介入有执行记录 | completed不是内容正确；没有因果证据证明工具质量是全部失败主因 |
| 经验使用 | 早期abstract未检索；v10唯一增益未用经验；v16状态改变真实 | 不能推断只要改检索或补齐组件就必定成功 |
| 操作学习 | v13查询和v15全局窗口由来源生成，但适用性和观察正确性未独立验证 | 没有已证明可学习、可迁移的条件化工具skill |
| 顺序保持 | 没有建立可靠的A阶段新增能力集合；v16的A输入相同 | 不能声称解决遗忘或保留了新获得的医学能力 |

当前最重要的机制问题是：能否学习“触发条件→缺失事实→有限动作→预期观察→独立验收→失败回退”，并在新患者上相对普通复核产生收益。完整skill可为学习产物；不要求预先手写整套临床流程，但必须有可执行原子动作和可靠的反馈/验收信号。

## 6. 下一步两条路线：当前建议，不是已执行结果

### 路线A：继续现有题库，但只补能改变决策的证据

仅在能获得原始病例依据、可靠标注或独立医学裁定时，回访少量具备明确动作假设的病例。需要先确认输入支持目标结论，再检验真实定位/分割/区域核查等操作是否带来正确观察和修复。不能继续在同三例上换框、改提示、追加重复挑有利输出。

优点是保留现有胸片工具与任务；限制是目前没有独立专家、部分源网页仍403，反复查模型文字难以补上真值缺口。96确认病例继续保护。

### 路线B：把下一主实验转到可验收操作的数据

| 候选 | 过程监督与工具联系 | 未解决条件 |
|---|---|---|
| [MS-CXR v1.1.0](https://physionet.org/content/ms-cxr/1.1.0/) | 1162组影像—描述配对，医生核验的病灶框与描述，提供患者级划分；与现有胸片定位工具更相近 | 需PhysioNet资格与DUA，图像另取自MIMIC-CXR；尚未核实本账号访问、本地配对图像和工具适配；还需核验基础模型数据重叠 |
| [BrEaST](https://www.nature.com/articles/s41597-024-02984-z) | 已有盘点记录；人工病灶掩膜、BI-RADS形态属性和像素尺度可支持区域/属性验收 | 超声领域工具与agent skill尚未验证，规模较小；保留既有冻结划分和封存测试边界，不能继承旧概念实验为skill成功证据 |
| 现有FETAL_PLANES、DERM12345 | 已核对类别和分组等数据条件 | 当前尚未确认足够的操作验收标注，不能仅因有分类标签就作为skill验证首选 |

当前倾向优先核实MS-CXR；若访问条件不具备，BrEaST可作为已有数据上的小型过程验证候选。不是承诺换数据一定有效，也不把定位基准优化取代Agent经验学习主线。

**拟议的最小资格链，尚未实施或冻结：**

1. 先定义受保护的医学对象、可观察事实和可执行动作，明确哪一项标注能验收该事实。若MS-CXR的征象描述作为输入，不能再把描述中的疾病名称当作新学会的诊断。
2. 仅在训练/内部开发材料上做单列上界诊断：提供预定义、可信的中间事实，检验下游错误是否有纠正空间；不提供最终诊断、答案字母或其同义表达。若给了目标框，不能把随后定位该框的分数算作非平凡收益。
3. 自主操作实验中，测试真值只进入评分器。比较普通复核、固定工作流、经验驱动工作流，保留工具/图像/token成本及正确病例误伤。
4. 在患者隔离的独立留出数据上，分别证明操作正确、观察正确和新增能力；有可重复获取证据后，再开展A→B及A新增能力保持。

需要Pro判断：路线A还欠哪一个低成本、可决定方向的诊断；或者当前验证条件已足以优先转向路线B。此处不预设答案，也不把未运行的上界与新数据方案写成结果。

## 7. 统计、资源与当前状态

## 9. 本次 Pro 回复后的核验补充（2026-10-26）

已阅读[本次分享中的审阅与benchmark检索](https://chatgpt.com/share/6adee71f-8d94-83e9-9365-3e392166580f)。以下为对关键事实的独立核验；原有实验结果、协议、分母和负结果不变，没有新增模型调用或重跑v17。

### 9.1 MS-CXR重叠风险已有具体训练证据

[MAIRA-2论文表1与数据说明](https://arxiv.org/html/2406.04449v1)明确列出MS-CXR训练817个配对、595名患者，并说明使用患者级留出；因此不能把整个数据集视为该工具未见数据。[CheXagent论文附录数据表](https://arxiv.org/html/2401.12208v1)也列出MS-CXR的定位、区域描述及区域诊断任务，训练/验证/测试实例为964/7/189，不能假定与MAIRA-2划分一致。

还需区分论文工具家族与实际checkpoint：当前原生工具对应[CheXagent-2-3b模型卡](https://huggingface.co/StanfordAIMI/CheXagent-2-3b)，其关联上述论文，但模型卡没有给出足以逐样本核验训练独立性的完整清单。实际权重版本、全部组件训练并集与拟用患者之间的映射仍未建立。

故前文“训练重叠尚待核验”应具体理解为：已有相关工具使用该数据集的明确训练证据，当前系统的患者级交集仍待核对。不能默认官方测试患者对整个六工具系统均未见，也不能反向宣称测试患者全部泄漏。同期、同工具条件下的harness配对收益仍可研究，但新患者泛化和新医学知识获得的主张受到额外约束。

### 9.2 v17存在长宽比失真，应补记为预处理混杂

`prepare.py`将所有裁剪直接resize为512×512。实际保存的映射表明，C03原裁剪192×360、C11为240×408、C13六个裁剪均216×336，8张图均发生非等比例缩放。几何框合法、来源绑定正确，并不代表局部形状比例得到保持。

这对空间关系和局部结构属性构成额外混杂，是此前报告应补记的限制。现有数据不能确认它导致零收益；不修订旧成绩、不将旧结果改写为无效后丢弃，也不据此重跑挑框救结果。未来新协议应保持长宽比，例如等比缩放配合padding，并保存原图/派生坐标变换。

### 9.3 单任务获取前需核实真实更新接口

当前公开`hcl/skills.py`的默认`min_source_tasks=2`，候选生成要求`tool_plan=[]`，产物主要是工作流/提示指导。单独学习A不保证默认skill准入条件得到满足。后续必须预先明确是更新memory/router，还是明确改变skill准入设计，并验证更新、检索、触发与实际执行。此事实不是v16失败的补充因果解释：v16本来就关闭skill层。

### 9.4 MedCTA值得接入审计，但尚未具备正式实验资格

本轮只核验[官方数据页面](https://huggingface.co/datasets/IVUL-KAUST/MedCTA)及官方仓库固定提交`eb7d1dc0adc6da4c31d9c5ebef3a8059a620022c`的README和两个评分文件，没有安装或执行其runtime。

- 数据页面公开107行、单一`train`划分，含问题、图像、工具链、轨迹与答案等字段；展示的schema中未见患者/源病例标识。因此107是任务数，不能当作107独立患者或现成的患者隔离持续学习划分。
- [README](https://github.com/IVUL-KAUST/MedCTA/blob/eb7d1dc0adc6da4c31d9c5ebef3a8059a620022c/README.md)区分`every_with_gt`和`every`。参考历史条件下的步骤预测与自主执行必须分别评价。
- [goal_accuracy.py](https://github.com/IVUL-KAUST/MedCTA/blob/eb7d1dc0adc6da4c31d9c5ebef3a8059a620022c/goal_accuracy.py)使用模型语义评分；提示允许预测包含正确答案且额外猜测不矛盾时获得满分。这是需要审计的反馈激励，不足以单独判定其已被利用或全部评分无效。
- 对[clinical_accuracy.py](https://github.com/IVUL-KAUST/MedCTA/blob/eb7d1dc0adc6da4c31d9c5ebef3a8059a620022c/clinical_accuracy.py)仅作静态AST解析，确认第17行发生`SyntaxError: cannot assign to function call`。这个文件不能按发布版本原样运行；该检查没有调用评分模型，也没有否定其他文件或论文结果。

若继续医学多模态主线，当前下一候选优先级可调整为MedCTA的来源独立性、评分和必要工具接入审计；MS-CXR保留为需要训练重叠核验的定位机制候选。它们都尚未进入正式训练/评估。Pro列出的PhysicianBench、MedAgentGym、ABRA等其余环境，本轮未逐一独立核验，也未据此把当前研究自动改为EHR或医疗代码任务。

下一里程碑仍应是：从训练反馈学得一个条件化操作策略，在适当隔离的留出材料上优于固定工作流，并能核验操作与有效观察之间的联系；通过获取门之后再进入A→B保持实验。
