# 共享工具正确性层的接入与验证

`qualified_tool.py`是后继实验的共同前置层，无可学习参数、来源经验或诊断知识。已有冻结实验文件和结果不改写。新运行先复用原`load_six()`，再执行：

```python
from qualified_tool import install_shared_guard
tools, state, Agent, prompt = runtime.load_six()
install_shared_guard(tools, state, record)
# 每病例开始：state["images"]只能包含已通过私有隐私审查的当前病例图片
```

安装只包装已有`chest_xray_expert`内层实例，保留外层调用预算、记录和其他工具。H0、Raw、Fixed、Proposed均须执行同一安装；不得以故障旧入口作为论文方法对照。`state`中的路径批准由实验准备层负责，此包装器本身不判定隐私是否安全。

准入检查原schema、当前病例路径和完整token预算；超窗明确失败，交由上层另行规划，不自动丢图。通过后仅归一首步空缓存，并检查真实视觉编码次数和图片数量；契约不满足时不向控制器提供可能无图的观察。错误通过原工具结果格式返回，追踪写入私有事件日志。工具正常完成依然不等于临床正确。

## D3固定集成检查

通过原作者MedRAX的`Agent.workflow.invoke`、原`BoundedTool`、新增共同包装器、真实CheXagent、`ToolMessage`回传走一次完整图路径。控制器是**脚本化测试替身**，固定返回工具调用并确认收到了工具消息；没有调用语言模型控制器，不是自然决策、六工具全链或效果试验。它只用于确保已经定位的修复真正应用于Agent调用路径。

固定两张D1/D2已审查开发图。四格包括两次单图合法请求、一次双图超窗请求和一次跨当前病例路径请求；后两格必须在生成前拒绝。共计划2次工具模型生成，0次控制器模型调用，未加载金标准。结果见GRAPH_INTEGRATION_AGGREGATE.json；本次直接验证采用BoundedTool的路径，六工具ObservedTool装配的实际运行另行核实，不声称已经全部验证。

## 后继边界

本项必要集成完成后不再扩大通用评测框架。下一步围绕MedRAX来源动作收益：优先核实可追溯图注或原报告的具体观察和监督，疑点来源继续待审，避免只用模型自评裁定临床事实。来源合格后再开展新版本的来源配对操作实验和匹配预算四组开发对照；保护集、医学收益和持续保持结论均不提前使用。
