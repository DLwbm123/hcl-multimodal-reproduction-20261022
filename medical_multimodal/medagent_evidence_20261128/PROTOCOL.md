# MedAgentBench 两来源取证试验

使用 MedAgentBench v2 原始 FHIR 快照与官方任务文件中 98 位有标识的患者。实验是新构造的回顾性只读任务，问题固定为从一条批准来源取回最近 24 小时内的任一真实数值记录。两路工具对应 MedAgentBench 的检验搜索与生命体征搜索，分别使用 GLU 与血氧观察编码。同一病例唯一共享首步是显示目标窗之前 48 小时的记录数和最近一次距今小时数；不展示目标窗记录、患者 ID 或正确动作。两臂都只能再调用一个来源，工具返回该来源在目标窗内的最近合格记录，最终提交由相同 Harness 确定执行。各方法均不写入 FHIR。训练评分计算在选取记录、患者及时间窗约束下的真实取得成功。动作之外的解析、工具接口、奖励与预算相同。策略只学习一个后续动作。

固定参考时间为基准工作流时钟 2023-11-13 10:15 UTC，每位患者用 0/24/48/72 小时四个截止点。病例和时间窗不按结果筛选。训练/开发/留出 54/20/24 名，患者互斥。四窗来自同一患者，配对统计以患者为单位。由于重用公开快照，分区仅承诺当前训练不重叠，不声称患者从未出现在历史基准工作中。

在开发侧枚举两个合法工具。最佳固定诊断参照允许按预先给出的截止点选一个全患者共同的来源，并用开发集事后最优各截止点所选来源作为更强上界；实际部署的固定来源和按时间点的固定表只用训练拟合。另报根据历史索引最近记录选来源的规则。只有病例逐一选工具的上界相对最佳固定诊断至少增加 5 个百分点，且增益覆盖至少两位开发患者，才启动 GPU。训练、开发、留出的窗口均保留成功/失败，双缺失不从分母去掉。留出直到选点冻结后才做枚举和策略评估；若未过门槛，直接按零训练进行一次留出诊断。

GPU 6 跑可用成功动作上的 SFT，并评冻结模型，GPU 7 跑 GRPO。固定 Qwen2.5-VL-7B-Instruct、语言层 rank-8 q/v LoRA、初始化、患者次序、单次源查询和每组采样数。两组各 64 步、4 个输入/步、学习率 2e-5。SFT 对训练例所有可成功来源的对数概率取平均，无可用来源时无监督梯度。GRPO 对采样执行成功给 +1，失败给 -1，组内中心化、KL 0.02。开发按总成功选点，同分取早；同时报告固定第 64 步。留出比较同接口冻结、SFT、GRPO、固定/索引规则和病例上界，报告来源使用频次及按患者配对差异。训练臂、对照和结果不在测试上调参。

用隔离 H2 副本，从 loopback FHIR 记录回执。只读访问复用官方数据、模型与运行环境。预计新增约 4.2 GB；FHIR 文件限制约 6.4 GB且服务独立超时，权重与日志另有约 1 GB 防护。本次从首次准备起硬截止 25 分钟。公开项目代码、协议、报告和聚合指标。所有真实行、患者列表、逐例输出与适配器留在私有目录。

准备阶段仅用开发侧候选患者核对源字段接线。原快照生命体征条目用 category=vital-signs，SpO2 以 code.text 和数值 valueString 入库。窗界在读取后依时间戳严格校验。较重的 HAPI 日期加排序查询在冷启动时超时，改为不排序的患者、来源和日期索引查询，并在本地复核窗界，调整发生在查看任何分区分数之前。

复现时，工作目录用 i0 链接已准备的官方快照运行目录（包含 config.yaml 与 data/test_db.mv.db），j 与 main.war 指向该快照的 Java 和 WAR。给 snapshot.sh 设置独立硬超时，在 loopback 就绪后用 prepare.py 读取本地 test_data_v2.json；关停这一私用进程后可离线枚举。仅在 gate.json 通过时使用 launch.sh，沿用前轮 env、PEFT 依赖、environment.py、train.py，并把 run.py 作为 t.py。SFT 与 RL 的实际 GPU 对照以门槛为准。
