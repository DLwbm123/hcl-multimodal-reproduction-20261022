# MedCTA 局部证据实验

在上一轮的 45 道配对评估题中，学习策略只请求过一次局部描述，坐标无效。此次把局部工具的参数选择改为封闭选项，并验证有效裁剪能否改善作答。另用训练样本量化定位的几何准确性。指标和运行限制在启动前写入 design.json。

## 定位和执行

冻结的 Qwen2.5-VL-7B-Instruct 看原图和同一图的十个候选预览。九个预览分别截取原图宽和高的一半，按三行三列排列，相邻预览重叠；第十个预览取原图中央 80% 宽和高。模型在合法字母中选择，程序从原图像素生成整数坐标。真正运行的 RegionAttributeDescription 将该区域裁出并调用准备好的 LLaVA 描述工具。相同题目中，已成功使用的区域从后续局部调用的选项中移除。模型选择时看不到参考框。两组使用完全相同的定位器、四个工具、每题最多四次请求、回答器和自动评分器。

## 训练和评估

- 延用 30 题反馈、16 题验收、45 题评估。HCL 记忆和一次 SkillOpt 编辑均在当前的真实工具返回上重新构建。按参考顺序尝试反馈阶段的动作。每道带局部参考的反馈题，在第一次局部请求处对照同一前缀加入局部返回前后的答案。评估模型按相同的参考接受条件独立打分。
- 对这些训练题的首个局部框，报告与参考框的交并比（IoU）、固定中央半幅窗的 IoU 和菜单内可达到的最高 IoU。超出边界的参考框裁到原图边界，同时报告保留在原边界内的参考框结果。交并比衡量与标注矩形的几何一致性，未经过人工判读。
- 候选必须在 16 道验收题上提高成功工具集合 F1 且答对数不降低才能替换基线。无论验收结果如何，均在原 45 题上运行两组并报告逐题改对、改错和工具成本。此面板已有历史实验记录，属于探索性复测。
- 把先前因参考轨迹需要搜索而排除的其余病例单独列为压力测试，排除与前述各组共用图像路径的题。搜索不可用，结果单报。原始问题、模型原始输出和记忆仅保存在私有运行目录。

## 复运行

沿用 round2/REPRODUCE.md 的 MedCTA 环境准备，包括同目录的 tool_server.py、共享的四工具运行时、冻结视觉模型和 HCL 记忆包。使用本目录 run.py、grounding.py、check.py、design.json，并从 round2 加载支持定位回调的 med.py 和 adapt.py。对新的 RUN_ROOT，先执行 python check.py 再执行 python run.py。最后运行 python analyze.py RUN_ROOT 取得不含逐例数据的成功调用、配对检验及靶框汇总。

如同时提供上一轮运行目录作为 analyze.py 的第二个路径，程序还会核对评估题编号，再报告各组相对上一轮同题的改对、改错。基线只替换了局部定位器，候选还在新返回上重新学习了策略。

## 仅反馈集的参考框对照

在主运行产出评估分数之前，独立冻结 design_control.json。在全程使用当前预测框的主实验外，fit_control.py 对相同训练前缀重放两次。一次用标注框与原来的通用属性请求，一次用同一标注框与标注者写的属性请求。两个条件都实际裁图和执行局部描述。比较换框前后及换属性前后的回答，缺少有效参照信息的病例排除，所有对照取相同病例。参考属性可能自带目标线索，这项对照只诊断工具可提供的证据。复用相同运行环境，将 fit_control.py 作为运行入口，使用 design_control.json 并设置 PAIRED_RUN 指向有完整反馈记录的主运行目录。

为定位策略是否采纳训练经验，analyze.py 还支持第三个路径参数，即推理问题清单 tasks.jsonl。在主运行的 Python 环境下，该项依照原检索函数重放每个已记录的决策状态，统计检索建议局部描述时策略实际执行或结束的次数。属于事后机制核对。

另行进行训练集内的探索性诊断。fit_evidence_gate.py 在每道反馈题上留出本题，仅使用其他反馈题首个局部请求前的可见状态。使用项目相同的词集合交并比，取最接近五例并纳入与第五例同分的病例。仅当邻近病例的局部描述平均净增答对数为正时，才将本题的局部描述交给回答器。该项事后检查只判断既有的轨迹检索可否预测证据收益，不用于选择主实验或改写验收结果。

## 一次停止复核

主实验的验收与旧 45 题的轨迹表明，候选在训练记忆建议局部描述时经常结束。另立 design_review.json，在查看压力集结果前冻结下列规则。如果候选已经选择结束、尚未尝试局部描述、还有调用预算，且本步检索的训练记录明确建议看局部，则仅追加一次局部描述并作答。两组仍最多尝试四次工具调用，该规则不要求每道题都有局部调用。

使用 stop_review.py 作为入口、design_review.json 作为配置，设置 PAIRED_RUN 指向主运行目录。16 题验证复用冻结基线和原候选的逐例记录，仅对改变的末步真实执行新工具并重新作答和评分。仅在工具种类 F1 高于修复后的基线且答对数不降时，才进入额外压力集；不再次评估 45 题。设计动机来自已见过的结果，验收只能视作探索性证据。
