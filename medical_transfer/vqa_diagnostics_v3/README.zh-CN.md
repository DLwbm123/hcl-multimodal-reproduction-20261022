# VQA v3：C瓶颈诊断与共同前态机制实验

在[v2最终报告](../vqa_local_v2/REPORT.zh-CN.md)完成并公开验证后冻结。v2仅学到color的7个新正确；局部A新增为空、C失败，完整目标未达成。两项均为开发诊断，不是新的临床或独立方法确认。合计最多8000次模型调用，共用一个23小时硬时钟和5GB新增存储上限（4GB停止写入）。P1优先启动；P2的A→B问题不依赖C修复，可同期运行。

## P1：最多2000调用，定位C

固定v2 Local-0的B后状态与空状态，使用原C选择24例。对B后状态只生成一次C首批24训练提案，比较少量raw、完整raw、完整raw加训练来源词面top2、再加训练词汇输出约束。abstract保持原状态，候选共用相同提案；强制检索与输出约束明确为诊断干预。允许的空间网格词从这24个训练标签导出，不能带入评测答案或按评测题型选记忆。

开发审计发现C的48个训练例有2个、24个选择例有3个缺失问题/目标标记。固定规则为问题空/nan/null/none，或目标空/nan/null；正常目标none仍合法。所有例保留在原生EM完整分母，另报不含上述标记的子集。原评分不做同义词替换、不改标签、不删除样本。

修复候选须在完整24例与未标记子集都比B后状态净增至少2例、格式100%；优先总正确数再按固定简单配置顺序。选完才评估新预留C开发复核24例与共同基准，复核只检验方向，不重新挑配置。没有合格候选则不打开复核推理，晋级失败。以已具非零成绩的B选择24例做真实图与预定循环错配图比较；当前图传入路径逐最终调用检查。全部为工程诊断，不能以地板效应或F1单独断言视觉能力。

## P2：最多6000调用，共同已学A状态

明确使用v2 Bulk-A作为探索起点H_A，已知历史报告对其选择有影响，不称独立确认。其raw10/abstract2构成共同满库前态。冻结两项独立单步更新：分别使用原B的两批24例，每块都重置为同一个H_A，不能解释成顺序B训练。

每块只生成一次共同proposal，再构造Local/Bulk各3种范围(raw、abstract、both)的候选。在同一B选择24+A锚点24上计算预测；同一预测离线复用到历史预算0和无限，不重复推理。两类预算都要求当前正确至少+1、主分数增加、格式100%；平局仍优先旧损失更少。raw容量与实际前态相同，Local替换最多2条并保留其他记录，Bulk对应整库替换；实际改写、保留/新条目、检索量和上下文长度全部记录。

使用新A开发复核24对空状态与H_A的差异定义新增集合G_A。若G_A为空，机制解释失败/不适用，不寻找另一个前态。对四策略在选择集选出的状态评估同一A/B复核48例，同状态复用预测，复核不参与候选选择。

每块机制模式要求：Local-0接受且B复核有正增益、G_A无丢失；Bulk-∞接受并存在锚点旧损失，而Bulk-0因历史预算拒绝。两块都满足才称该探索模式重复出现；两块共享数据与前态，不是两次独立确认。Local-0和Local-∞相同不算硬门控的额外贡献。A/B共同前态继续学C须先有P1的C学习证据，未纳入本轮预算。

## 数据、记录与执行

沿用v2的288个训练/选择/锚点开发组；新增72个此前未使用的h_search组显式预留dev_review（A/B/C各24，每题型12）。按元数据选组、持久化成员后才关联答案，排除全部历史组与像素，原test和v1/v2报告组均不使用。没有患者独立性主张。

新增开发过程记录每个训练交互后的raw状态、共同proposal、候选状态和预测，修复v2因未记录而无法追溯的证据缺口。公开仅汇总，私有图像/答案/成员/预测/记忆状态不发布。

模型、原生评分、已有环境和模型路径只读复用。独立监督、每次调用预算与陈旧守护检查、单一30分钟监测；每进程中性入口。任一路工程故障停止本轮所属进程、保留证据与原时钟，不自动重启。最终记录所有负结果、门槛与缺失证据，不按复核结果延长或修改候选家族。冻结细节见[protocol.json](protocol.json)；实际起点和启动检查将在FROZEN/STARTUP_RECEIPT记录。
