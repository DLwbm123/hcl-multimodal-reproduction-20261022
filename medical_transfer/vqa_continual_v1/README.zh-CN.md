# VQA 连续学习与保持：A→B→C 冻结协议

用户于2026-10-24明确授权按第二份分析推进，先冻结协议与必要对照再启动。本轮回到已有VQA正信号的主线：连续获得新收益后，先前收益是否保留，以及历史保护门槛是否提供额外作用。

## 划分与可见性

- A：存在/是否类问题 + 计数；B：颜色集合 + 器械；C：位置集合 + 选择/其他。
- 每阶段学习48、选择验证24、历史锚点24、报告评测72，均按两种类型均衡。每阶段2批，每批24条学习反馈。
- 共504个内容组、504个像素身份，每组仅1条问题，阶段之间和角色之间完全分离。排除882个历史已用内容组；不读取test。
- 先用原有问题类型/角色/身份元数据进行全局二部匹配分配，冻结成员清单，再关联答案。阶段标签只存于评估元数据，所有样本task_name均为visual_qa；不按阶段/子类型过滤检索。
- 旧代码会按task_name排除当前任务锚点，本轮仅在隔离worker的train调用中显式替换为“更早阶段”过滤，并在异常时恢复。每个已完成阶段的24个锚点原样累积，不再按同任务覆盖或聚类缩减。

准备失败保留：初始每阶段100个报告组不可行。排除历史组后，五种非presence类型合计仅253个validation内容组，而原均衡配额需310组。未写冻结成员清单、未模型推理前，一次性改为72/阶段，对应需要240组。使用全局分配避免顺序抽样耗尽稀缺组。阶段定义、学习/选择/锚点数和5个百分点效应门槛保持原定值；原始预算起点不重置。

## 必要对照

1. Direct：同图像与可见问题，固定模型直接回答。
2. Static：同一固定harness，无记忆、无更新。
3. 固定规则记忆：与HCL相同的raw10/abstract2容量、学习反馈、冻结模型抽象生成与历史证据边界；无候选搜索和接受门槛，固定词汇重合top2检索，无条件批次写入。因此它是固定更新/检索策略对照，不是“完全无LLM的记忆”对照。
4. Plasticity：记忆更新及memory_selector候选搜索；严格当前选择验证收益、格式和结构合法性门槛；历史损失预算B=∞。
5. Stability：与Plasticity仅B=0不同。历史答对→错独立计数，恢复其他错误不能抵扣。

固定已有Qwen2.5-VL-7B BF16、temperature0、SDPA、生成上限2048/答案512；参数冻结。从空状态开始，不选择历史最佳checkpoint。首轮只搜索memory_selector，每批最多3候选；不优化接口、workflow、context或baseline，不开展工具/定位支线。所有记忆条件关闭skills，避免增加容量与机制混杂。原有模板结构契约及历史记忆边界复用。

## 冻结评估与结论门槛

在空状态与A/B/C后形成完整4×3矩阵；每阶段相同72个独立报告组，只读执行，不用于接受候选、选择checkpoint或调整下一阶段。Direct/Static各只计算一次216回答，矩阵复用明确记录。其他条件在每个节点实际评估。每阶段另记录所有已完成阶段锚点的正确数、有效保护分母与类型覆盖。

同时报告：立即学习增益、最终平均准确率、相对Static和固定记忆的配对差异、A/B在获得能力后被后续学习破坏的逐例数量、恢复数量、最差旧阶段、BWT、每阶段接受更新数，以及学习/部署分别的调用、时间和显存。按内容组做固定seed的20000次配对bootstrap。全分母保留失败。

- 学习与保持联合通过：Stability最终平均比Static至少高5pp且配对95%下界>0；平均立即学习增益至少5pp；B或C至少一次接受更新；A、B各自最终丢失的原正确病例不超过72组的5%（最多3例）。零更新不能支持有效学习。
- 门槛机制归因：Plasticity必须实际存在旧病例丢失；Stability丢失更少且配对差值95%上界<0，同时平均立即学习增益落后不超过5pp。否则只能报告不确定或不支持。
- 超过固定记忆的优势：最终Stability−固定记忆配对95%下界>0才作该主张。

一条流、一个seed；内容组独立不等于患者独立。旧冻结VQA正结果及三任务失败均保留，本轮不追改历史结论。

## 运行边界

规范远端根目录为既有项目下的新独立vqa_continual_v1；只读复用模型、环境与数据，不下载新权重。GPU2运行Stability，GPU3运行Plasticity，GPU4依次运行Direct/Static/固定记忆。入口与子进程使用中性文件名。

原始时钟从首次准备开始，22.75小时提前停止、23小时硬截止；每HCL最多18000调用，controls共7000。预计新增不足1GB，4GB触发停止、5GB本轮上限，严格低于用户50GB上限。独立监督每10秒检查实际占用、时间与退出状态，逐调用检查守卫新鲜度，硬超时与SSH/Codex无关。仅按PID/启动ticks/进程组/完整argv匹配终止自有进程；任一路fatal故障停止本轮其他条件，保存部分结果与原始时钟，不自动重启。

公开范围仅源代码、冻结协议、聚合检查与报告；成员、标签、图像、逐例预测、具体运行配置与状态留在服务器。唯一30分钟监测负责状态、完成分析、主线后继实验及交付；冻结运行中不改变数据或门槛。
